# Design

## Context

动机见 proposal.md。当前 design/moss.rs 仅枚举 CUDA，moss/candle/design.rs 再次强制 CUDA。实际使用的 DelayModel、runtime::device 与 model_dtype 已存在 Metal/F16 路径，codec 已用于 MOSS Realtime Metal。design 路径尚未像 runtime::run 那样在模型加载与 codec 加载间同步 Metal 上传，取消检查也在模型加载后才发生。

DelayModel::generate 已在 EOS drain 完成后成功返回，超出 max_frames 会报错；不需要为了此次移植重写生成调度。设计入口当前 max_frames=125，不能通过放宽完成规则来接纳截断音频。

docs/records/moss/moss-macos-performance-baseline-2026-10-24.md 记录旧 local-1.7B Metal 在 24 GB 上 OOM；那不是本次 VoiceGenerator 实测，但足以要求独立内存门禁。docs/records/tts-core/voice-studio-2026-10-26.md 的真模型设计与跨后端音色验收仍未执行，不应当作可靠基线。

主 specs 为空；本变更复用 voice-studio 的 voice-design 能力路径，新增 Metal 专项要求，不复制或改写其资产、协议规范。旧 change single-voice-narration-experiments 的滚动实验不作为本次路线。

## Goals / Non-Goals

**Goals:** Metal 设计有明确可验证路径；交付批量旁白候选及固定参考克隆对照，供用户集中试听。

**Non-Goals:** 不扩展 MOSS 朗读模型档位、不开放 CPU 设计、不更换 Candle/ORT/权重、不引入自定义 Metal kernel；不建立通用批处理平台或新 wire 命令；不恢复滚动参考；不自动选中或发布默认音色；不把批次试听当成整章验收。

## Decisions

### D1 — 复用现有设备路径，先验收再声明

在现有 moss-candle-metal feature 下修改设计层的能力枚举与前置校验；显式 Metal 使用 F16 模型和 F16 codec，CUDA 保留 BF16 模型和 F16 codec。加载前、模型后、codec 后及生成阶段检查取消；Metal 组件加载间同步，避免异步上传叠加。沿用 owner 线程 join 和库的原子入库语义。

替代方案“只去掉 CUDA 判断”缺少资源与实机证据，不采用。若实机 OOM/算子失败，记录真实阻塞，不篡改设备声明、不静默回退。仅允许修复有具体证据的局部布局/加载问题；新量化或依赖升级另提变更。

真实门禁包括：一次中性短句设计、一次不同 seed、加载/生成取消后的再运行，以及输出 WAV 和转写核查。记录设备、模型修订、dtype、耗时、音频时长、RTF 和峰值内存；能取得 Metal 资源指标时记录，不用进程 RSS 冒充 GPU 峰值。

### D2 — 首批矩阵与文本

固定 seeds 为 42、20261031。每个引擎 8 个画像各 2 项：

| ID | 画像方向 |
| --- | --- |
| m-young-clear | 青年男声，清晰自然，中音区 |
| m-warm | 成年男声，温暖沉稳，轻微磁性 |
| m-mature | 中年男声，低沉克制，口齿清晰 |
| m-elder | 年长男声，温和有阅历，避免过度沙哑 |
| f-young-clear | 青年女声，清澈自然，避免尖细 |
| f-warm | 成年女声，温暖柔和，避免气声过重 |
| f-mature | 成熟女声，沉静知性，中低音区 |
| f-bright | 成年女声，明亮利落，保持叙述克制 |

均为普通话、自然语速与中性叙述，不要求模仿真人。画像描述在编写批次输入时冻结并进入指纹。

Qwen VoiceDesign 与 VoxCPM 各 16 项为首批。MOSS Metal 门禁最多使用 20 分钟计算时间（不含显式权重准备），通过后追加 16 项。OmniVoice 暂不加入，避免扩张样本矩阵；需要时另开明确批次。

共同参考文本拟为“清晨，窗外的风渐渐停了。她合上书，起身走向门口。”，在执行前冻结；目标约 5–8 秒但不承诺模型必然满足。测量实际时长，超出共同克隆后端限制则标记不适用，不裁剪凑长度；ASR 仅辅助发现漏读，最终转写以实际音频核查为准，不把错误正文静默写成正确转写。

### D3 — 资产与批次编排

优先在 scripts/voice_studio_acceptance.py 旁增加用途明确的批次操作脚本，调用既有 voices design/export 与 Rust 合成/导出入口。先核对当前可用导出接口，避免依赖音频设备回录。无需修改生产协议或用户配置，所有动作使用显式引擎、设备和候选 id。

候选 id 含批次、画像、引擎与 seed，长度符合现有约束。生成结果进入现有库并标记为批次候选（在批次清单保存人工状态，不改库格式）。target/voice-candidates/<batch-id>/ 保存 JSON 清单、原始参考/可搬运包、试听音频、index.html 与 feedback.csv；导出保留原字节。HTML 用相对路径和原生音频控件，无服务器或网络依赖。

每项状态分离 design 与 preview，以及 pending/running/succeeded/failed/blocked。保存内容指纹、资产 ID、文件摘要、实际 revision/设备/dtype/配置、完成时间与安全错误。设计成功后即原子更新清单；导出/试听失败仍保留库身份，恢复时核验后接续，避免成功入库与清单更新之间中断导致重复生成。

每项设计至多 600 秒、试听至多 300 秒、准备每引擎至多 15 分钟，整批运行上限 6 小时，每项每阶段自动尝试一次。进程超时先取消并等待子进程/原生任务释放再启动下一项，不让孤儿进程占用 GPU；显式恢复可再尝试失败项，保持原身份和历史。配置变化必须新建执行，不覆盖旧音频。MOSS 的附加批次排在 Qwen/VoxCPM 之后，失败不影响基础候选交付。实际任务可能少于 48，索引必须说明原因，不承诺固定时刻全部完成。

### D4 — 统一固定参考试听与人工决策

每个有效参考以同一 VoxCPM2 权重/设备、固定 seed 7、同一 80–120 字原创中文多句文本进行克隆试听；不得以无参考 narrator 代替物化失败的候选。参考音频冻结后不回灌生成结果。试听正文包含叙述与简短对白但不切角色，不加特殊风格，先观察基准声线与连贯性。

每条索引提供参考、克隆试听、画像、引擎/seed、状态、时长及疑点。反馈列为喜欢程度、自然度、音色稳定、清晰度、是否愿意长听、备注；全部留空等待用户。未通过完整性检查的项保留失败记录，不伪装可听。不同设计引擎在同一克隆后端比较，便于区分设计质量与朗读实现；后续选中候选再扩展其他后端和整章验证。

### D5 — 验证与交付顺序

先做无模型的设备清单/前置拒绝/取消失败不入库测试，批次工具通过替身验证恢复、超时、同名保护和索引链接。再完成相关 CPU 测试、fmt、Clippy、rustdoc 及原生 Metal 构建；CUDA 使用对应环境编译/回归，当前机器不能验证的部分明确记录。真实模型测试只在显式执行步骤准备权重，不混入普通测试。

## Risks / Trade-offs

- [MOSS 模型与 codec 叠加导致 24 GB OOM] → 单 owner 串行、同步加载和独立门禁；失败仍交付基础批次。
- [重新加载权重使大批次缓慢] → 首轮复用现有入口保证正确，记录时间；不为提速改模型常驻生命周期。
- [短参考的口误或表现被克隆继承] → 同时展示参考和另一文本试听，保留疑点，不自动选胜者。
- [未提交 VoxCPM 性能改动影响归因] → 实施前记录 dirty diff 与构建来源，不覆盖现有改动；报告构建不是纯 main。
- [产物泄露或误入默认库选择] → 音频只放忽略目录/用户库，唯一候选命名，不修改默认配置或用户旧音色。

## Migration Plan

无需迁移。代码改动可独立回滚；新增候选保留为用户资产，回滚不删除。试听结果通过本地索引交付；只有人工明确选定后，后续任务才考虑默认旁白或预置资产打包。
