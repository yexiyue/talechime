# Design

## Context

动机见 proposal.md。负责实现的项目是 `/Volumes/yexiyue/talechime`，不是作为消费者的 CastGlean。已有未提交代码提供了若干参数和文本边界调整，但不能假定它们已经发布或通过完整听验。

当前证据入口为 `docs/knowledge/plans/tts-backend-parity-audit-2026-11-11.md`、各模型 `SOURCE.md` 与模型资源 manifest。`tools/tts/text-matrix.json` 有 13 条公开用例；现有 Python 执行器只有生成/失败/超时状态、CPU 路径和原始日志，尚不覆盖完整能力身份、适配后文本及音素证据。CosyVoice3/IndexTTS 使用受校验原生资源配方；引擎对象有 owner 线程约束。

## Goals / Non-Goals

**Goals:** 逐模型闭合已识别的官方推理缺口；使日语分词和资源可复现；保留原文映射；用统一用例提供可审计的官方对照、真实音频及听验状态。

**Non-Goals:** 新模型家族、训练工具、CUDA/Metal 优化栈移植、发布或部署。Nano 漏读与音色调优及中文年份产品策略暂后置；仍运行回归并记录失败，不将它们包装成官方能力已通过。

## Decisions

### 1. 固定官方基线和显式能力账本

沿用当前 `SOURCE.md` 与 manifest 中的 revision，对每个公开模型变体建立“官方支持 / 本地实现 / 官方对照 / 真实生成 / 听验”的独立字段。先检查旧变更已有结果，复用可追溯证据；历史数据缺 revision、输入或设备时补跑。不能因模型家族名字相同而合并验收。

| 后端 | 需闭合的具体路径 |
| --- | --- |
| Qwen | Auto 动态 prefill、Eric/Dylan 方言；CustomVoice、Base ICL、VoiceDesign 各自条件与多语言真实验证 |
| OmniVoice | 未指定语言的 None 条件，设计与参考音色路径；显式语言、速度和生成控制实际生效 |
| IndexTTS 2.5 | 官方平台中英 TN、日语分词、西语 TN、阿语路由、时长倍率、读音标注、独立情绪参考/向量及 QwenEmotion |
| CosyVoice3 | ZeroShot、CrossLingual、Instruct 输入边界；文本前端与参考转写处理；复核既有数值差异 |
| MOSS | Nano/Realtime 固定版本 prompt、分词、已公开控制与 EOS/取消边界，不引入其他 MOSS 家族功能 |
| VoxCPM2 | 原始权重与 Q8 分开验收；克隆、风格、设计、跨语言、特殊文本与停止边界 |
| Kokoro | 原版与 g2pW 音素路径、英文未知词回退差异；明确中文模型对假名/emoji 的拒绝边界 |

替代方案“先只开放几个参数”无法证明模型收到正确条件，因此不作为完成标准。

### 2. 模型适配器拥有文本语义

宿主继续传原文，TN/G2P 位于模型库或对应适配器。公共用例是输入集合，不是全后端强制改写步骤。内部诊断仅为测试/维护工具提供受控文本阶段快照，不改变 JSON Lines v7 或把引擎类型暴露给宿主。

中文年份读法与官方基线分别验证。当前宿主无逐段语言元数据，不能将“含汉字”视为明确中文条件；本变更不增加无依据的强制年份转换。后续产品读法策略应依据明确语言条件或用户读音意图，并保留日文和歧义输入。

### 3. 日语默认语义先准确对齐

IndexTTS 固定上游 `d9e41aac89fd00b3d71497fddb287b7f24613712` 的 `infer_v2_5.py` 使用 `JapaneseG2PProcessor(g2p_ratio=0)`，日语 NeMo TN 透传。实现顺序保持清理、大小写、标注、日语分词及特殊标记处理与上游一致；连续 ASCII 空格的分段拼接行为也需对照。

参考环境固定 fugashi 与 unidic-lite 版本并保存词典内容身份。Rust 候选为 Vibrato 0.5.3，采用与参考匹配的 UniDic 数据和 MeCab 兼容选项；先验证词典来源、未知词长度和空格处理对分词边界的影响，再接入推理。候选不能通过对照时改为移植匹配的词典读取与 MeCab 分词算法，不用近似分词器代替。默认 ratio=0 不引入随机假名替换；其他 ratio 不作为本模型公开控制。测试包括汉字、假名、片假名、无假名日期、外来词、标注及连续空格。

### 4. TN 与情绪组件使用现有资源生命周期

IndexTTS 中英 TN 以固定官方实际配置为基准：macOS/Windows WeText 与 Linux 参考分别核对。现有 wetext-rs 三例探针只作候选证据；完成更广的 oracle 对照、FST 许可及固定摘要后方能替代近似规则。西语 TN 固定官方 NeMo grammar 与配置，不能把依赖安装失败时的官方降级当成正常基线。

QwenEmotion 单独固定模型、tokenizer、模板、输出解析及八维情绪顺序；先用独立官方输出验证，再接入 IndexTTS。文本情绪模型未就绪时明确缺件，不以关键词规则冒充。保留用户直接向量与独立情绪参考的官方优先关系。

新增词典、FST 和情绪权重通过既有准备配方的来源/revision/size/SHA/许可证契约下载与发布；推理不依赖用户 Python 环境。前端资源和算法版本进入缓存身份，不能跨语义版本复用音频。

资源 revision 与代码中的文本/语言条件算法分开：`ResolvedModel::text_semantics_revision()`
提供共享算法身份，宿主应同时冻结它和 `revision()`。同一批语义修正保守失效全部旧算法
身份，不为了代码修正复制未改变的权重；引擎已有执行缓存身份同时记录该字段。
该接口只提供明确身份，不自动修改宿主任务或已有音频。

### 5. 矩阵分层执行并持久记录

扩展现有 corpus 与 runner，预先生成“后端 × 公开模型变体 × 适用用例 × 设备/模式”的计划。首要执行本机 CPU 实际路径；已声明支持的 Metal/CUDA 单列构建与实机证据，设备不可用不冒充通过。Qwen Base 的参考音频语言等变量须固定，额外参考语言对照单列。

逐行记录源码及构建身份、资源摘要、原文 hash/UTF-8 范围、执行文本/音素或 token、语言/模式/seed/参数、非私有参考来源、分段及 PCM 校验、EOS/错误/超时、生成耗时和 WAV 路径。不承诺跨框架采样音频逐字节相同；确定性的前端与条件结构要求对齐，适用数值路径沿用各模型容差并注明量化差异。

runner 使用新输出目录、参数数组和有界执行；超时保存部分日志并确认子进程退出。缺模型和崩溃保留为阻塞/失败，缺失行由计划与结果差集检查，不能静默少跑。报告只收录白名单配置，不保存凭据、原始环境或私人内容。

### 6. 听验交付及阶段门禁

同一公开输入的音频在试听索引中并排显示后端、变体、音色、语言、执行文本及已知问题，逐项记录完整性、读音、连贯性和音色异常。ASR 可提示缺词，不能代替听验；已有人工失败不能被 EOS 或重跑覆盖。

分三种结论：能力实现及自动/真实门禁完成；矩阵全部计划行已执行或明确阻塞；人工听验通过/失败/待听验。仅在范围内实现和必需生成验证全部通过后交付“可听验版本”；用户尚未试听时只能报告听验待确认。Nano 失败是后置修复项，明确保留，不能宣称全产品音频质量已通过。

### 7. Kokoro 英文未知词

Kokoro 使用固定版本的英文词典与神经未知词后备；不使用独立辅助进程。英文专名和虚构词的读音与官方参考可能不同，需单独进行人工听验；范围、资源和语义身份见 `kokoro-mixed-language` 变更。

## Risks / Trade-offs

- [词典同名但分词不同] → 固定内容摘要并与同版本 fugashi 逐例对照，失败时不开放日语入口。
- [FST/词典许可或上游获取失败] → 在实现任务中保留具体阻塞，不改用未核验第三方资源或近似回退。
- [大型模型耗时和内存] → 一次一个模型，逐行落盘，有界超时并保留资源准备与推理阶段差异。
- [官方本身生成漏读或年份不符合产品预期] → 分开官方一致性与产品听验，不把模型限制虚报为移植遗漏已修复。
- [旧变更与工作区修改重叠] → 应用前登记任务归属，复用已有修改；不覆盖 CastGlean 并行工作或删除历史产物。

## Migration Plan

1. 将旧变更剩余任务与证据映射到本任务集，旧 delta 的归档/同步在完成时统一处理，避免主规格重复。
2. 新前端与资源配方使用独立语义版本，验证后切换；保留既有模型目录和音频。
3. 核对宿主原文传递及恢复兼容契约，若需要修改宿主语言元数据或数据格式，另行扩展其变更后实施。
4. 2026-11-11 用户明确允许不兼容及清理旧音频：语义身份变化时可直接使旧任务/音频缓存失效并重建，不增加迁移或双路径兼容。范围内旧音频可清理；原文及本轮失败验收证据仍保持独立。宿主任务续跑必须核验当前文本/模型身份。
5. 更新各领域文档、README、知识库及 OpenSpec；提交/发行/部署不属于本规划阶段。


## 2026-11-12 设备验收范围调整

用户明确选择“先完成本机，CUDA 实机项另行安排”。当前交付范围为本机适用能力与
真实矩阵；原始 VoxCPM BF16 的 19 条 CUDA 行仍为未验证，保留在完整报告并交给
`deferred-cuda.md`。不改变其真实设备限制，不用 Metal/CPU 或结构 fixture 替代 CUDA
编译、数值和实机音频门禁。其余本机失败仍须继续处理。
