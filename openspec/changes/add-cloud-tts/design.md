# Design

## Context

现有 `VoiceLibrary` 保存带转写的本地 WAV，`VoiceStudio` 和本地 Engine 独立；本地播放管线使用 LocalSet、PCM 和实际消费进度。云服务返回网络音频，远端音色可能随账号和权限变化。详见 proposal 和两个 delta specs。

## Goals / Non-Goals

**Goals:** 独立编译与发布，提供可测试的 Fish HTTP 边界，保留 provider 特性与不确定性。

**Non-Goals:** 不把云端 ID 纳入本地 v2 资产格式，不提供章节/角色管理或播放适配。

## Decisions

1. **独立 crate 与轻量公共层。** 新建 `talechime-cloud-tts`，不依赖 core、模型或播放器；公共请求描述文本、模型、音色来源和格式，Fish 专属参数留在 provider 模块。先不承诺跨 provider 完全一致的 trait：一个实现不足以证明抽象。备选直接放 backends 会强迫宿主携带本地依赖。
2. **显式模型及音色来源。** 允许已知 Fish 模型枚举，明确免费和付费选项；不得透传未知模型触发服务端付费回退。音色区分远端 ID 和参考样本，不能同时隐式选择。远端引用带 provider；账户上下文由宿主管理，不存密钥。
3. **HTTP 流和完成。** 响应作为带格式元数据的有界字节流；不假定网络块是音频帧。仅正常 HTTP body 结束且存在非空音频判为传输完成，不证明语义完整或播放完成；截断检测受 HTTP 协议和格式验证能力限制。drop/cancel 关闭本地响应，不承诺远端停止计费。长度与错误体均设上限；宿主负责解码和播放。
4. **两条克隆路径。** 即时参考以 MessagePack 发送原始音频和对应转写；持久克隆通过 multipart 显式创建并返回 ID、状态，再通过查询确认。调用方从本地库取样本，不更改库或持久化凭据。远端创建超时视为结果未知，不自动重试。
5. **目录与错误。** Fish 列表提供公开/自有范围、分页和支持的过滤条件，查询保留远端字段必要信息；认证、限流、服务错误、传输错误与未知结果类型化。限制错误体大小并清理敏感内容。连接注入及受控 endpoint 用于本地 mock，生产默认 HTTPS。
6. **能力延伸。** Voice Design 返回多个候选但按次计费，作为后续单独能力；多角色请求、表达标签、WebSocket 增量文本、余额与播放适配均留后续，不能据此声称已支持。音频格式、采样率及服务默认值在实现时以当前 OpenAPI 和实测核验。

## Risks / Trade-offs

- [免费服务期限与政策变化] → 模型显式选择，不承诺免费可用或付费回退。
- [流正常结束仍可能漏读] → 分开传输完成与内容正确性，真实语音和试听单独记录。
- [上传隐私和音色授权] → 文档说明数据出境和服务条款，调用方显式提供数据及决定授权。
- [服务端参数或状态演进] → 返回未知状态并明确失败，不静默映射为成功；实现前核对官方 schema。

## Migration Plan

新增可选 crate，不迁移任何用户数据；撤销变更只移除该 crate 和文档，不操作远端音色或既有本地资产。
