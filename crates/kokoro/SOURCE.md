# Official Kokoro native inference

Acoustic reference: https://github.com/hexgrad/kokoro
Revision: `dfb907a02bba8152ca444717ca5d78747ccb4bec` (0.9.4).
Files: `kokoro/model.py`, `modules.py`, `istftnet.py`.
License: Apache-2.0, copied as `LICENSE`.

Talechime reimplements the official tensor layouts, inference operations and
single-segment behavior in Rust/Candle. It folds weight normalization during
development-only export, supports explicit excitation fixtures and bounds
duration expansion. No third-party Rust Kokoro implementation is used as a
source or correctness reference. Upstream derives neural modules from
https://github.com/yl4579/StyleTTS2 (see upstream source comments).

Chinese frontend reference: https://github.com/hexgrad/misaki
Revision: `fba1236595f2d2bf21d414ba6e57d25256afada3` (0.9.4), Apache-2.0.
Its `zh_frontend.py` and `tone_sandhi.py` adapt PaddleSpeech:
Copyright (c) 2021 PaddlePaddle Authors. All Rights Reserved. Apache-2.0.
Frontend implementation/data acceptance is tracked separately from acoustics.

Official Chinese weight/config/voice source:
https://huggingface.co/hexgrad/Kokoro-82M-v1.1-zh
Revision: `01e7505bd6a7a2ac4975463114c3a7650a9f7218`, Apache-2.0.
`kokoro-v1_1-zh.pth` SHA-256:
`b1d8410fa44dfb5c15471fd6c4225ea6b4e9ac7fa03c98e8bea47a9928476e2b`.

Weights, generated audio, full real-model fixtures and external checkouts are
not distributed in this crate. Python is used only by development export tools;
native runtime inference does not invoke it. GPU features do not imply device
acceptance; see dated records under `docs/records/kokoro/`.

CPU moment reduction additionally follows PyTorch 2.7.1
`aten/src/ATen/native/cpu/moments_utils.h`, `layer_norm_kernel.cpp` and
`FlashAttentionKernel.cpp`:
https://github.com/pytorch/pytorch/tree/v2.7.1/aten/src/ATen/native/cpu
The BSD-style license is preserved as `licenses/PYTORCH-LICENSE`.

https://github.com/GitYCC/g2pW
Revision `b9328ce8129c4717a70f16a2688542a0197541dd`, Apache-2.0.
Author model: https://huggingface.co/YC-Chen/g2pW/tree/fb4784f7dce8466a53dd4f3552f5a4c5b657b90c
`G2PWModel-v2-onnx.zip` SHA-256:
`699f3c1fd7fb0e2c2d49ed2486826fd5bff233fee7759350a91c3b49aedc4ed2`.
Extracted `g2pw.onnx` SHA-256:
`bb40c8c7b5baa755b2acd317c6bc5a65e4af7b80c40a569247fbd76989299999`.
Tokenizer vocabulary: https://huggingface.co/google-bert/bert-base-chinese/tree/8f23c25b06e129b6c986331a13d8d025a92cf0ea
(Apache-2.0), SHA-256:
`45bbac6b341c319adc98a532532882e91a9cefc0329aa57bac9ae761c27b291c`.
Context exports retain the official g2pW license; the pinned BERT vocabulary is
used without separate BERT weights. g2pW predictions precede existing Misaki
sandhi; they do not silently alter the faithful `1.1-zh` baseline.

English mixed-text frontend: TaleChime's `talechime-loqui-g2p` fork of
`loqui-g2p` 0.4.0 (MIT), upstream commit `717691aadf67408c85d87dc33e5d1d77b2ea4b4d`.
It retains Misaki 0.9.4 lexicons (Apache-2.0) and spaCy tokenizer data (MIT),
but removes the embedded neural model. A fallible callback at the actual
unresolved-token branch invokes a separately distributed eSpeak NG phonemizer; no
GPL code is linked into the Rust library. Fork sources and notices are in
`third-party/loqui-g2p/`. The host supplies or discovers a pinned bundle;
missing resources fail on an OOV word rather than changing pronunciation.

## Mixed-language oracle (2026-11-11)

The Mandarin reference is Misaki `fba1236595f2d2bf21d414ba6e57d25256afada3`.
For the explicit English callable, the fixture uses its US `en.G2P(trf=False,
unk='')` and `EspeakFallback(british=False)`, following Kokoro's English
pipeline at `dfb907a02bba8152ca444717ca5d78747ccb4bec`. Kokoro's Chinese
pipeline accepts a caller-supplied English callable; this is one specified
configuration, not an assertion that all callers use it. The oracle pins
spaCy 3.7.5 and `en_core_web_sm` 3.7.1 (wheel SHA-256
`86cc141f63942d4b2c5fcee06630fd6f904788d2f0ab005cce45aadb8fb73889`),
phonemizer-fork 3.3.2 and espeakng-loader 0.2.4 (eSpeak NG 1.52.0 on this macOS run). The exporters verify source
revision, dependency versions and installed model files against the wheel.
The complete version list is in `tools/tts/kokoro_mixed_oracle.py`.

`tests/fixtures/mixed-misaki-espeak.json` is independently generated by those
Python sources. `mixed-g2pw-espeak.json` uses the same Misaki frontend and
independent official g2pW predictions per Mandarin span, before Misaki tone
sandhi; g2pW is Talechime's optional extension, not an official Misaki mode.
The exporter pins the g2pW model, tokenizer and exported mapping table hashes.
`english-oov-espeak.json` records the fallback in isolation; it does not prove
that a word reaches fallback through Misaki's full tokenizer. Scripts under
`tools/tts/kokoro_*_oracle.py` take explicit local source/resource paths and
write only new output files. Runtime uses a separately distributed eSpeak NG
1.52.0 phonemizer; it does not load the GPL library into the Rust process.

On macOS CPU, using the built 1.52.0 bundle and pinned frontend/g2pW exports,
11 of 13 full mixed cases match per variant, including the OOV case; all three
isolated OOV words match. The remaining `year_spaced_product_policy` reads
`2026 年` as a year, unlike official cn2an, and `unsupported` rejects input
where Misaki emits its unknown marker. Both are explicit product policies.
g2pW predicts `han4` for
the isolated Mandarin span `和` in `english_words`; its independent fixture
confirms the implementation, but does not establish that pronunciation is
contextually desirable. Human listening, more OOV vocabulary and other
platforms remain unverified.

Run `cargo test -p talechime-kokoro --features g2pw --test mixed_oracle --
--ignored` with `KOKORO_FRONTEND_DIR`, `KOKORO_CONTEXT_DIR` and
`TALECHIME_ESPEAK_DIR` pointing to the pinned exports and bundle. The strict
`mixed_compare FRONTEND BASELINE_JSON CONTEXT CONTEXT_JSON` reports every
comparison and deliberately exits nonzero on the two documented product-policy
differences. The no-feature example accepts FRONTEND and BASELINE_JSON only.
The bundle manifest pins source identity and hashes every listed file; this is
an integrity check against the manifest, not an authenticity signature. The
host/distribution must supply the trusted bundle and verify its provenance.
The standalone phonemizer receives a newline-terminated word over stdin. A word longer than 255
bytes, or an eSpeak data path exceeding its platform buffer, is rejected.
Cancellation requires callers to use `segments_cancellable`,
`phonemes_cancellable` or `phonemes_with_context` and pass the owner signal;
the non-cancellable convenience methods do not observe an owner signal.
Human listening, other platforms, real desktop integration and release remain
separate acceptance steps.

The separate `tests/fixtures/fullwidth-percent-misaki.json` records the pinned
Misaki 1.1 result for `你好％`: `ㄋㄧ2ㄏㄠ3❓`. Regenerate with
`tools/tts/kokoro_mixed_oracle.py --fullwidth-percent-only` and the same pinned
inputs as above. The native frontend rejects `％` as unsupported; the fixture
is evidence of a difference, not a parity pass. This does not change the
historical 13-case counts above or reclassify real synthesis failures.

2026-11-12: the standalone `kokoro-espeak-phonemize` calls the fixed
`espeak_TextToPhonemes` API with the same voice, UTF-8 and IPA tie mode as the
official Misaki callable. The general eSpeak CLI added sentence-final stress to
function words (for example `de`), so it is retained for general use but is
not used as the frontend phonemizer. The bundle contains the GPL adapter C
source, exact eSpeak source archive, builder and licenses. The manifest
`phonemizer_protocol` prevents older CLI-only bundles from being reused.
The independent 20-word official fixture includes function words and OOVs.
