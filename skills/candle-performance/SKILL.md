# Candle 性能优化

把性能问题转成可验证的假设，保留有证据支持的改动。适用于各类 Candle 推理模型；
TTS 是经验来源，不是目标项目必须采用的结构。按用户要求区分调研、讨论和实施，
不因使用本 skill 自动开始长时间模型运行、安装工具、修改系统配置或发布上游 PR。
已在当前任务授权范围内的检查与实施沿用既有授权，不重复请求确认。

## 建立判断依据

读目标仓库规范、当前源码与 Cargo.lock，确认设备、dtype、模型/输入、feature 合并后
的实际计算路径和完成语义。优先找固定形状重建、重复参考计算、主机往返、小算子
分派、布局物化和 KV 写入；不要仅凭 GPU 利用率低就判定分派受限。

确认比较的是冷启动、prefill、decode、首结果、稳态吞吐还是内存。只加载当前需要的参考：

| 当前问题 | 参考 |
| --- | --- |
| 计时、退化、结果一致性、验收设计 | [测量与准确性](references/measurement.md) |
| Metal 的排序/卷积、小张量与主机同步 | [Metal](references/metal.md) |
| macOS CPU BLAS、AMX、线程争用 | [Accelerate/AMX](references/accelerate-amx.md) |
| CUDA/cuDNN、CUDA Graph、内存与流所有权 | [CUDA](references/cuda.md) |
| Candle issue/PR、fork、feature 和发布兼容性 | [上游与依赖](references/upstream.md) |
| 需要比照已有成功/失败案例 | [案例与证据](references/case-studies.md) |

先提出最小可证伪实验：它改变什么、预期减少什么成本、如何排除输出和计时口径变化。
已有产物可复用时，先核对源码、配置和输入对应关系，再复算逐轮统计与输出摘要；
不要把历史计时重命名成当前代码的新基准。只有新改动或证据缺口才补测。
先编译后测量；正式 GPU 计时期间不并行编译或推理。无匹配硬件/本地权重时，完成
源码调查、夹具与编译验证，明确实机未验证，不下载模型或编造实测结论。

## 默认验收策略

默认要求同后端、同配置的优化保持输出。复制、缓存、图回放要做逐位/逐字节对照，
包括重复调用、特化切换、取消与状态复用。固定 seed 不能替代完整输出比较。

切换 BLAS、归约/卷积/GEMM 形状或精度时，先判断是否可能改变数值。
若现有任务已授权容差，遵循该约定；否则先展示数值变化和建议门槛，讨论后再把它
作为目标方案推进。不通过放宽容差、改变采样、缩短上下文或提前结束来获得“提速”。
跨设备/框架不能默认逐位相同；把性能优化、准确性修复与质量取舍分别立基线。

先筛选再扩大测量，报告逐进程均值、范围和原始轮次。显著性与收益门槛按任务成本和
已有约定确定；Talechime 某轮的 10% 门槛不是通用要求。没有明确收益时，撤回以提速
为目的的候选；纯简化独立说明理由，并验证行为。不累积失败实验的运行时开关。

## 实现与交付

按所有权划分模型算术、设备执行机制、请求状态与宿主适配。图/缓存持有其引用资源，
低层模块不读取宿主业务配置。用 KISS/DRY/YAGNI/SOLID 检查真实耦合；两个真实消费者
共享相同语义后再提取公共模块，且提取发生在第二个消费者通过性能门槛之后：
先在消费者内做私有原型，门槛通过再把设备机制提取为独立 crate，模型策略留在
私有模块。不为单个候选预建框架，也不让未过门槛的候选占据共享抽象。

交付应说明：问题与证据、最终保留/撤回的改动、输出及状态对照、性能测量口径、
设备和未验证范围。把可复用结论与带版本的实验记录分开保存；不提交模型或用户音频。
版本、API 和 PR 状态从当前源码/官方资料核实；历史案例只提供实验方向。
