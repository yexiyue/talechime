# 整篇/段内语气衔接：滚动接续之外的上游调研

日期：2026-10-29。背景：滚动参考、双参考与重锚实验已于 2026-10-27 全部移除（见[官方固定参考收敛](official-reference-synthesis-2026-10-27.md)），生产收敛为固定参考独立请求。音色身份稳定性由此获得，但"整篇与段落内句子语气自然衔接、有起伏"仍未解决。本调研回答：不把生成音频回灌为下一块条件的前提下，业界与学术界还有哪些路线。本轮未下载模型、未修改生产默认、未执行真实模型实验。

## 结论与边界

滚动接续不是唯一被否定的路径，ElevenLabs 的 request stitching 在机制上属于同一类（服务端以上一块生成结果为条件），同样不纳入。除此之外存在六条实质不同的路线：

1. **组段与切分策略**（已有方向，可升级为篇章结构感知切分）——近期、零新依赖。
2. **长上下文原生模型**（TADA、VibeVoice：单次生成 11–90 分钟，架构性消灭接缝）——远期、新后端。
3. **文本侧韵律规划**（LLM 先给整章打三层韵律计划，再逐段合成）——中期主线候选，与 CastGlean 小模型计划协同。
4. **同音色多参考（情绪参考库）**（按剧情情绪选固定参考，不回灌）——中期，依赖后端参考分离能力。
5. **质量控制环**（声纹相似度自动检测漂移块 + 换 seed 选择性重生成）——近期，工程兜底，不产生衔接但保证耐久。
6. **接缝音频工程**（crossfade、块间停顿规划）——与用户"不补静音/不掩盖"的既有边界冲突，需单独拍板，本轮不推荐默认采纳。

证据分级沿用[滚动上下文调研](rolling-context-research-2026-10-26.md)：官方代码与文档证明接口存在；论文证明机制与研究验证；社区评测与博客只提供现象与口碑，不是质量承诺。所有路线均未经本项目中文长篇听感验收。

## 逐路线证据

### 路线一：组段与切分策略（结构感知）

现状即基线：语义组段在模型 token/时长预算内合并相邻句（[固定参考合成](../../reference-synthesis.md)），其思路是"接缝越少越自然"。上游佐证：Amazon Polly long-form 引擎接受 10 万字符、内部按约 1500 字符分段；OmniVoice 官方建议约 15 秒目标分段、30 秒触发切分；VoxCPM [PR #313](https://github.com/OpenBMB/VoxCPM/pull/313) 提议语义分段（截至 2026-10-26 仍 Open）。

可升级点不在"多长"，在"在哪里切"：按叙事结构选切分点（场景切换、对话轮次边界、自然段结尾优先），避免在语气延续的句子之间硬切。这不是模型能力，是宿主分块策略，Talechime 现有分块层可直接承载。

风险：单次生成变长后长文本失真是已知问题（VoxCPM [issue #372](https://github.com/OpenBMB/VoxCPM/issues/372)，IndexTTS [issue #775](https://github.com/index-tts/index-tts/issues/775) 末句对齐坍塌）；切分粒度仍需逐模型验收，无通用阈值。

### 路线二：长上下文原生模型（新后端）

- [TADA](https://github.com/HumeAI/tada)（Hume AI，[论文](https://arxiv.org/html/2602.23068v1)）：文本 token 与连续声学向量逐对对齐，宣称架构上杜绝漏读/多读；每秒音频仅 2–3 token，2048 token 上下文容纳约 682 秒连续语音；开源 1B（英文）与 3B 多语言（含中文），Llama 3.2 底座，支持短音频克隆 prompt。限制：单说话人。
- [VibeVoice](https://huggingface.co/microsoft/VibeVoice-1.5B)（微软，MIT，2025-08）：1.5B/7B，每秒 7.5 token，64K 上下文单次最长约 90 分钟，最多 4 说话人零-shot 克隆，流式推理。中文口碑分裂：社区实测基础版对中文走"拼音 + 英文韵律"路径（[WebUI 中文教程](https://blog.csdn.net/weixin_42510201/article/details/158170773)），另有宣传原生多语言的 Pro 部署版（非同一开源权重）。中文质量必须实测，不能按英文评测外推。
- [CSM-1B](https://huggingface.co/sesame/csm-1b)（Sesame，Apache-2.0）：RVQ + 音频上下文条件，为对话衔接设计；但跨片段同一音色保持是[社区活跃问题](https://huggingface.co/sesame/csm-1b/discussions/58)，长篇一致性未验证。它属于"模型内部管理上下文"，与宿主滚动机制不同，但效果风险同源，不优先。

定位：这是唯一"消灭接缝"而非"接好接缝"的路线，与档位=范式的架构一致，可作为未来新档位评估。成本：Candle/ORT 移植 + 中文质量验收，量级等同一次新后端接入（参照 CosyVoice3/IndexTTS 移植周期）。

### 路线三：文本侧韵律规划（LLM 先规划后合成）

代表：[Borderless](https://arxiv.org/abs/2603.19798)（2026-03，闭源）用 agent 在生成前做三层标注——全局（场景、情绪弧、说话人名册）、句子（篇章上下文、韵律边界、轮替）、token（发音、时序、强调）——以规划换取跨句自然与可控起伏。学术依据同向：[ContextSpeech](https://arxiv.org/abs/2307.00782)（跨句文本上下文 + 记忆复用）、[有声书 TTS 声学与文本上下文韵律改善](https://www.researchgate.net/publication/371287106_Improving_Speech_Prosody_of_Audiobook_Text-To-Speech_Synthesis_with_Acoustic_and_Textual_Contexts)（2023）。

工程化形态：整章先由 LLM/小模型产出"韵律计划"（每段落：情绪档、语速、停顿风格、强度），宿主把计划映射到各后端已有的显式风格输入——VoxCPM `(description)text`、CosyVoice3 instruct、IndexTTS 2.5 情绪参考+强度、Qwen 1.7B style、OmniVoice instruct。关键性质：每块输入 = 固定参考 + 确定性韵律标签，完全可复现、无误差累积；且"整篇起伏"只有全局规划视角给得了，逐块接续原理上给不了。

与生态契合：语义判断归 LLM/小模型（CastGlean 小模型计划的既定分工），韵律标注是典型判断题，可进同一蒸馏管道。风险：标签到听感的映射逐后端验收；需守住"不逐句人工导演"纪律——LLM 规划粒度应到段不到句。此路线不要求新模型权重，只要求现有后端的风格接口真实有效。

### 路线四：同音色多参考（情绪参考库）

机制：为同一音色准备多条不同语气的固定参考（平静叙述/紧张/低语……），组段时按剧情情绪选参考。每次输入仍是固定参考，无生成音频回灌；身份靠"同库参考彼此相似"保证，语气靠选参考提供变化。IndexTTS 2.5 原生支持音色与情绪参考分离及强度控制（[官方 infer_v2_5.py](https://github.com/index-tts/index-tts/blob/main/indextts/infer_v2_5.py)），是现有后端中最直接的载体；VoxCPM [issue #302](https://github.com/OpenBMB/VoxCPM/issues/302) 的讨论方向（连续注入说话人身份、身份与韵律分离）与之同族但属研究假设。

建库方式可用本产品已有能力：对同一音色用不同风格指令生成候选参考，经试听与声纹相似度筛选入库（类比 VoxCPM 已验证的"默认音色生成后冻结参考"做法）。风险：参考间音色相似度需预验收（可复用路线五的度量）；支持参考分离的后端有限。

### 路线五：质量控制环（检测漂移，选择性重生成）

[arXiv 2604.06327](https://arxiv.org/html/2604.06327v1)（2026）提出首个针对扩散式 TTS 的说话人漂移自动检测框架：块级说话人 embedding 余弦相似度，按二分类判漂移。相似度度量与人感一致性有[先前依据](https://assets.amazon.science/54/25/8841c2c64d0db183b9f2be49aa35/automatic-evaluation-of-speaker-similarity.pdf)（Deja et al., Interspeech 2022）。

工程化：对整章各块计算声纹相似度矩阵，标记离群块，换 seed 重生成后复检。Talechime 已有全部地基：门禁重试本就"改 seed 不改参考"；ASR 回读是 issue #2 的既定方向，可与声纹检测合并为同一个长篇质量门禁。定位注意：此路线不产生衔接，只保证问题块被自动定位与替换——把"用户听 25 秒才发现音色变了"变成生成期自动标记。纪律不变：自动指标标记疑点，不选胜者、不替代听感验收。

### 路线六：接缝音频工程（需用户拍板，本轮不推荐默认）

社区工程实践：句边界切分 + 约 50ms crossfade 消除拼接爆音（[VoiceBox #363](https://github.com/jamiepine/voicebox/issues/363) 提议）；有声书排版的块间停顿规划（段内句间短停、段落边界长停）。与既有纪律的冲突点：用户已明确拒绝参考补静音、削头、调速与掩盖式处理；crossfade 与停顿规划属于"接缝排版"而非"掩盖缺陷"，但边界需要用户逐项拍板，本轮不默认采纳任何一项。

### 云端并行路径（既定计划的延伸）

云 TTS 后端已拍板接入（MiniMax 首选）。商业厂商普遍在服务端维护长篇上下文（ElevenLabs request stitching、Polly long-form），机制上 stitching 仍属"上一块音频条件"一类，由厂商规模化验证与维护。按"本地免费改稿、云端付费终稿"的既定定位，整章终稿可直接评估云端整章接口的质量，不改变本地主线结论。

## 对 Talechime 的建议

1. 近期（零新依赖）：升级组段为篇章结构感知切分（路线一）；把块级声纹相似度检测并入 issue #2 的 ASR 回读门禁（路线五）。两者都只在既有分块层与门禁层扩展。
2. 中期主线候选：LLM 韵律规划（路线三）映射到各后端显式风格接口，先在风格接口最强的 IndexTTS 2.5 / VoxCPM / CosyVoice3 试点；与 CastGlean 小模型计划共用蒸馏管道。同批可试 IndexTTS 2.5 情绪参考库（路线四，改动最小）。
3. 远期评估：TADA-3B-ML / VibeVoice 作为新档位立项（路线二），先做中文短样实测再谈移植；VibeVoice 中文口碑分裂，未实测不进计划。
4. 需用户拍板才动：crossfade、块间停顿规划（路线六），与"不补静音/不掩盖"边界逐项确认。
5. 所有路线共用既有验收纪律：短样→细化→整章→换 seed 复现；自动指标只标记不选胜者；不回灌生成音频。

本轮为桌面调研，未修改 OpenSpec 任务、生产默认或任何代码。
