2026-11-05，macOS。配套 CastGlean 下载任务实现；没有发布 SDK、没有推送。

## 真实公网短时对照

固定文件与此前诊断相同：`OpenMOSS-Team/MOSS-TTS-Realtime`，revision `75682787d8e2fcc73faca37ba2931453ca9c4022` 的 `model.safetensors`，4,663,931,664 字节。每次独立缓存，从零开始，目标 8 MiB 文件字节、最多 30 秒；计时包含进程启动、元数据、传输、取消后的断点保存与退出。预算检查可能让多连接略超 8 MiB。未加载或下载完整模型。

结果支持当前链路上适量并发有用，但四路未优于两路。默认选择每文件 2 路、全局最多 4 路；API 允许 1–4。样本小且受链路、CDN 缓存和顺序影响，不承诺稳定倍速，也不能外推整模型耗时。

初始试跑因临时元数据请求失败而没有数据，不计作成功测速；保留“存在链路波动”的限制。最终六次均成功观察到真实字节。解析后的数据 URL 在文件内复用，避免每片重复请求 Hub；过期时单次串行刷新并验证内容身份。

复现（示意缓存请使用自己的独立临时目录）：

```sh
cargo run -p talechime-backends --no-default-features --example download_progress_probe -- bridge /绝对路径/独立缓存 https://huggingface.co 2 30 8388608
```

末尾参数为连接数、秒数、文件进度字节预算。日志不输出签名 URL 或令牌；失败返回非零退出状态。不要用正在下载的用户缓存做测速，也不要把小样本当成完整模型验收。

## 本地确定性验证

普通测试不访问公网。`downloads_parallel.rs` 使用拥有明确生命周期的本地 HTTP 服务、真实流式 body 与固定 payload，验证五组行为：

1. 不同缓存/客户端同时下载时，活跃下载请求峰值不超过全局 4；结果与已知 payload 完全一致。
2. 下载中丢弃 future 后读取分片断点，新建客户端以各片保存位置继续；不按稀疏文件长度判断完成。
3. Range 被忽略时单流回退；坏 Content-Range 与 SHA-256 不符不发布产物；503 有界重试。
4. 过期地址并发 403 时只刷新一次，内容身份变化拒绝续传。
5. 注入断点原子替换失败，停止后 `checkpoint_failed()` 可见，调用方不能确认已持久化暂停。

27 项后端单元、5 项本地 Hub 集成、5 项分片集成均通过；配套宿主 38 项普通测试与 specta 导出通过。相关 fmt、Clippy、严格 rustdoc 通过，前端构建和 Lingui 767 条文案严格编译通过。macOS 界面使用隔离缓存与合成响应验收暂停/重启/继续（134 MB 恢复后增长至 200 MB），该项不证明权重有效。Windows 的新增交互和完整模型下载/推理尚未实机验收。
