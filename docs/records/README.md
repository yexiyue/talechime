# records/ 归档规则

2026-10-20 后旧 `tools/` 目录已删除。历史记录中的 `tools/tts/...` 是当时的路径，脚本可从 Git revision `e591c94` 取回；历史命令不代表当前可运行入口。固定验收语料现位于 `crates/voxcpm/tests/fixtures/acceptance-corpus.txt`，原字节未改变。

本目录存放特定日期、版本和设备的历史验收与实验结论，是只增不删的台账：记录当时的边界（未通过项、未执行的试听、已中断的验收）与原始结论，不代表所有平台或模型均已通过验收。当前能力以 `docs/` 根部指南和源码为准。

## 目录划分

| 子目录 | 主题 |
| --- | --- |
| `plans/` | 实施计划与路线图（含已退休计划的演进背景） |
| `tts-core/` | 与具体后端无关的引擎能力：参数/seed、风格、播放、缓冲、解耦与基线 |
| `cosyvoice3/` | CosyVoice 3 移植、验收、审查与性能 |
| `indextts/` | IndexTTS 2.5 移植、验收、审查与性能 |
| `moss/` | MOSS 后端各阶段验收与实验 |
| `qwen/` | Qwen TTS 后端验收 |
| `voxcpm/` | VoxCPM 移植与平台性能 |
| `asr/` | ASR 回读校验选型、验收与标签能力 |
| `continuation/` | 跨段/段落内接续能力 |
| `voice-drift/` | 音色漂移实验与对照 |
| `platform/` | 跨后端的平台与原生依赖变更（Metal、ORT 等） |

## 新记录怎么放

- 放入最贴合的主题子目录；单一后端的事进该后端目录，跨后端或后端无关的引擎改动进 `tts-core/`，平台/依赖升级进 `platform/`，纯规划进 `plans/`。
- 文件名 `<主题>-<性质>-YYYY-MM-DD.md`（如 `cosyvoice3-performance-2026-10-17.md`）；同主题多轮迭代用日期区分，不覆盖旧记录。
- 真模型数值、音频与性能验证与普通测试分开记录（普通测试不下载模型）。
- 链接写法：同目录直接用文件名；跨目录用 `../<子目录>/<文件>`；指向 docs 根部指南用 `../../<文件>`。

## 搬迁既有记录

只更新路径引用，保留验收日期、设备、未通过项与原始结论。
