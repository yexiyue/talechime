# Kokoro CPU：缓冲复用、归一化与向量 sin（2026-10-27）

状态：本机实现及验收完成，未发布。本轮基线是[上一轮最终实现](kokoro-cpu-parity-2026-10-27.md)，包含之前的窗口展开、存储借用和 Snake/AdaIN 优化。

## 保留的实现

- macOS CPU 卷积的窗口 Vec 归各 Weights 所有，按已用最大尺寸复用；只在需要扩大时 reserve_exact/resize。每次覆盖完整使用区间及 padding，保留 SGEMM 几何、beta=1 和 bias 预填充。CPU 输入/权重仍按原策略借用；无全局缓存。Mutex 保留底层模型的自动 trait，计算同步完成后归还锁，模型释放时释放 Vec。
- CPU AdaIN 把 learned normalization affine 与 style affine 放在同一次行遍历，保持每一步 F32 舍入，不合并系数。串行、尾行和分组路径共享同一 affine helper。
- 大张量以四个独立行组成统计任务，交错执行四条 F64 累加链；每一行仍按时间索引递增累加，没有分割行内归约或合并部分和。小张量和不足四行的尾部走原路径。
- 大型 CPU Snake 的向量 sin 以 64K 元素分块交给同步 Rayon 任务，至少 256K 元素才并行；继续调用原 Sin::f32_vec，未换标量 sin。新增整块、单元素尾部与更大张量逐位检查，并检查完整 PCM。
- 依赖、模型、前端词表、dtype、随机输入、分段与音频后处理保持原配置。生产库没有覆盖全局线程数或增加实验开关。

代码：[CPU 卷积](../../../crates/kokoro/src/blas.rs)、[算子](../../../crates/kokoro/src/ops.rs)、[模型所有权](../../../crates/kokoro/src/lib.rs)。

## 归因与筛选

本轮起点在四线程下重新 profile，声学总耗时约 4.095 s：普通卷积 2.013 s、Snake 0.500 s、转置卷积 0.448 s、AdaIN 0.445 s（含 InstanceNorm 0.408 s）、BiLSTM 0.108 s。嵌套项不相加。激励信号只有 0.034 s，即使完全消除也不足声学耗时的 1%，因此没有改写它。

初期同四线程六进程按“基线→AdaIN→加缓冲→加缓冲→AdaIN→基线”运行，每进程 1 预热 + 3 热轮；长文均值分别 4.8516 / 4.7110 / 4.4025 s，组合约减少 9.3%。这是早期原型筛选，后续改为 Mutex 与精确保留容量；最终收益见正式序列。

八线程下再做独立 ABBA：多行统计的长文控制组 3.9205 s，候选 3.8488 s；向量 sin 的控制组 3.8554 s，候选 3.5123 s。各过程完整 PCM 均逐字节一致，收益不按百分比相加。

线程筛选包含原生 BLAS/Rayon 的 4/4、4/8、8/4、8/8，后续增加 8/12、12/12；官方 PyTorch intra 为 2/4/8/12。最终双方采用八线程配置。筛选为独立进程每案例 1 预热 + 3 热轮，不作为最终快慢排名。

## 正式同机对照

Apple M4 Pro（12 CPU / 16 GPU）/ 24 GiB / macOS 26.6.2；Rust release/LTO、CPU F32 Accelerate、Candle 固定 fork 884b359895a16c8fbd3647789b1f7c7974894708。未证明 AMX 硬件分派。官方源码/权重 revision 与上一轮相同，Kokoro 0.9.4 / PyTorch 2.7.1 / ORT 1.28；详见上一轮来源记录。

“官方组合”为固定官方 Kokoro、Misaki 和作者 g2pW 的本地适配器，g2pW 结果在变调/儿化前注入，声学代码未修改。Kokoro 官方没有该集成开关。双方使用同一 v1.1-zh、zf_001、speed=1、每段 seed=7、冻结六段/一段输入，g2pW ORT CPU 均 2 线程。

两种原生版本均使用 VECLIB_MAXIMUM_THREADS=8 / RAYON_NUM_THREADS=8；官方 torch intra=8 / inter=1，VECLIB=8；OMP/OPENBLAS 均为 8。优化前后采用相同原生线程数，代码收益与线程调整分开。

正式组件按“旧原生→新原生→官方→官方→新原生→旧原生”（ABCCBA）运行；公共 Engine 另按 ABBA。每组两个独立进程，每案例 1 预热 + 5 热轮，全部热轮保留；先算进程均值，再平均两个进程。范围为进程均值范围，不是置信区间。

组件包括中文前端、声学和取得主机 PCM，排除加载、冻结分段及写盘；原生拼接 PCM 的复制计时，官方返回 NumPy PCM。Engine 消费至显式 Completed，包括生产分段、边界静音、响度处理和通道交付，排除 prepare、写盘与播放。两入口音频长度不同，分别计算 RTF。

先冻结二进制并完成编译，正式计时不与本任务其他推理/编译并行。未锁频，保存进程及 thermal 快照。断盘中断的 sin 序列作废并移至 interrupted；筛选只取恢复后完整序列，正式数据全部在恢复后生成。

## 内存观测

固定组件长文在缓冲原型上测得 decoder 保留 306,161,152 字节、encoder 5,566,464 字节，合计约 297.3 MiB；最终沿用相同窗口形状与保留策略。这是复用容量，随模型释放，不等于进程峰值增加量。窗口仍完整展开；缓存容量、空闲时保留量与进程峰值分别讨论。

正式进程通过 macOS /usr/bin/time -l 同时采集峰值 RSS，包含加载和预热；组件同进程覆盖两种语料，不能把峰值归到某一个案例。

## 准确性与状态门禁

- 正式原生序列 48 份完整 F32 PCM 与旧版逐字节一致；所有正式官方/原生轮的音素、整数时长和样本数一致。
- 五组官方夹具覆盖女声标准/慢/快、男声短/长句，CPU/Metal 十组通过既有 SNR>=40 dB 及 duration_equal 门槛，完整 PCM 同时与旧版逐字节一致。门槛未放宽。
- Engine 原版/g2pW 完整 PCM 分别与原试听逐字节相同；CPU/Metal 同 seed 重复、首 PCM 前取消、取消后复用和 close 通过。同一裸 Model 的短文→六段长文→男声→女声→男声交错也通过字节检查。
- 默认 CPU 与 g2pW+Metal 的模型库各 19 测试通过，2 项真模型测试默认忽略；后端 51、facade 8 测试通过。opt-in 整模型和固定特征解码器两项通过原有 40/60 dB 门槛。
- 三包全 targets Clippy -D warnings、严格私有 rustdoc、cargo fmt --all --check 通过。只验证本机 CPU 性能；Metal 做数值和生命周期回归，Windows/Linux/CUDA 未做实机验证。有限输入的字节一致不等于所有输入的形式化等价。
