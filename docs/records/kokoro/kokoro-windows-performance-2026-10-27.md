# Kokoro Windows 输出保持型性能优化（2026-10-27）

基线：从 `23c7d3e` 快进到 `origin/main` 的 `0d3ce5a`，应用版本 0.6.1。
本轮没有升级 Candle、ORT、模型、词表、精度或生成参数。

## 实现

- Windows CPU 的宽卷积原先使用 Candle 串行 im2col。新增模型私有 `cpu_conv.rs`，
  按独立 batch/time 行同步并行构造窗口；保留 `[batch, time, channel*tap]` 的
  矩阵形状、权重布局、K 顺序和独立 bias 加法。小矩阵仍串行构造，没有窗口容量缓存。
- 把既有 macOS 保序转置卷积移到 `cpu_transpose.rs`，Windows CPU 也使用它。
  仅限 F32、groups=1、padding>0；每条输出行内仍逐 tap 累加，调用相同 Candle
  vector-dot。无 padding、depthwise、其他 dtype 和 GPU 卷积保留原路径。
  macOS 只是移动实现，没有在本轮重新实测；Linux 路由保持原样。
- `performance::verify/load` 补齐 Kokoro 的本地转换清单和生产 owner 接线，复用
  生产格式、音色、读音模式与逐文件摘要校验，拒绝越出资源根的文件。
- 新增显式本地夹具 `performance` example，分开记录完整声学到主机 PCM 的计时、
  每轮原始 F32 PCM、整数时长、重复和中途取消后的逐位恢复。既有 Engine 探针增加
  不同长度、已安装的另一音色及取消后回到原 pinned 请求的检查。

没有新增原生依赖、运行期开关、全局线程设置、自动下载或用户数据迁移。

## 环境与资源

Windows 11 家庭版 10.0.28000，Ryzen 7 9700X（8 核/16 逻辑线程），约 15.2 GiB
可见内存，RTX 5070 12227 MiB，驱动 616.56，CUDA Toolkit 13.0。
Rust 1.98.1 / x86_64-pc-windows-msvc，release、opt-level=3、LTO。
Candle 0.11.0 固定 fork `884b359895a16c8fbd3647789b1f7c7974894708`。
CPU 是纯 Rust GEMM；CUDA 是 CPU 编码器/时长/F0/FFT 与 GPU 解码器的混合执行。

全部 A/B 使用相同 `RAYON_NUM_THREADS=8`；16 线程另作筛查，不在库中固定线程数。
使用平衡电源计划，未锁频。CUDA 编译继承 `NVCC_PREPEND_FLAGS=-Xcompiler=/MD`；
保留仓库已记录的 CUDA 13 driver-loader `LNK4098`，未屏蔽或宣称修复。

用户授权后，官方来源与权重按 [SOURCE.md](../../../crates/kokoro/SOURCE.md) 的
固定 revision 下载到 Git 忽略目录。PTH SHA-256 为
`b1d8410fa44dfb5c15471fd6c4225ea6b4e9ac7fa03c98e8bea47a9928476e2b`。
实际导入的 Kokoro/Misaki 源文件经既有导出器逐文件校验，音色为 zf_001 / zm_010。
Git 自动 CRLF 导致首次来源校验失败；新建参考 checkout 改为保留 LF 后重试，
没有放宽 SHA 检查。权重下载的初次 TLS 错误与成功重试日志均保留。

本轮真实模型只覆盖 `1.1-zh`；`kokoro-g2pw` 做普通测试和构建检查，没有新建 g2pW
真实资源，也不据声学收益推断它的整链性能。

## 测量口径

固定两段自建中文测试输入，另有女声快/慢及男声夹具。没有使用用户小说或参考录音。
声学入口固定官方 ID、style、speed、显式随机激励；包括完整 forward 与获取主机
PCM，排除加载、前端、原生随机数生成、检查和写盘。生产入口直接执行现有
`performance_probe`，覆盖生产分段、前端、原生随机数、音频处理与完整消费至
`SynthesisState::Completed`；排除准备/加载和导出，不包含实际音频播放。
两者音频长度与随机流不同，分别计算 RTF，首 PCM 为完整模型片段交付延迟。

新旧二进制独立冻结，先编译后串行测量，不与本任务其他编译或推理并行。
各输入按 ABBAABBA 八个独立进程，每个进程 1 预热 + 5 热轮；全部热轮保留。
先计算各进程均值，再平均四个进程；范围是进程均值范围，不是置信区间。
父进程采集包含加载与预热的 PeakWorkingSetSize，不能解释为某个算子的容量。

这是针对本轮改动的独立实验，复用了 Rust 生产探针及其逐轮事件/资产，父级脚本只
串行调度、采样和复算；没有冒充 `xtask perf` 全矩阵冻结、审计及发布报告。

## CPU 交错结果

以下均为同一 Windows / F32 / 8 线程配置，非 macOS Accelerate。原生生产请求
短文输出 2.760 s、长文输出 10.920 s 音频，新旧输出长度与完整 PCM 相同。

| 生产整链 | 版本 | 合成秒数 | RTF | 进程均值秒数范围 |
| --- | --- | ---: | ---: | --- |
| 短文 | 原版 | 1.1262 | 0.40804 | 1.1126–1.1502 |
| 短文 | 优化后 | 0.8700 | 0.31521 | 0.8403–0.9233 |
| 长文 | 原版 | 3.9965 | 0.36598 | 3.9725–4.0182 |
| 长文 | 优化后 | 3.2055 | 0.29354 | 3.1788–3.2440 |

生产短文耗时减少 **22.7%**，长文减少 **19.8%**；本样本的首 PCM 约等于完整片段
交付，分别为 1.1261→0.8699 s、3.9962→3.2052 s。不是原生流式首块。

| 固定官方输入声学 | 音频秒数 | 原版秒数 / RTF | 优化后秒数 / RTF | 耗时减少 |
| --- | ---: | --- | --- | ---: |
| 短文 | 3.375 | 1.1683 / 0.34615 | 0.9103 / 0.26972 | 22.1% |
| 长文 | 11.575 | 4.1254 / 0.35641 | 3.3444 / 0.28893 | 18.9% |

声学进程均值范围：短文原版 1.1539–1.1741 s、新版 0.8975–0.9368 s；长文原版
4.1017–4.1582 s、新版 3.3167–3.3840 s。有限样本区间不重叠，不称作统计显著性证明。
正式 CPU 声学与生产各有 80 个热轮，全部完整 PCM 分别在各自输入内逐字节相同；
声学的整数时长也相同，每个声学进程均通过重复与中途取消恢复。

采集的进程峰值工作集：声学短文约 630 MiB、长文约 917 MiB；生产短文约 638 MiB、
长文约 1044 MiB，新旧无明显变化。本轮不宣称降低内存。16 线程的独立长文初筛为
3.7874→3.0786 s，完整 PCM 相同；只有每组一个进程、两热轮，不参与正式统计，也不
把显式 16 线程称作 Candle/Rayon 未设置环境的默认配置。

## 补充：同机官方对照与 Mac 目标

用户明确要求对标官方及 Mac 后，另运行固定官方声学入口的原生/官方 ABBA：每输入
两个原生、两个官方进程，各 1 预热 + 5 热轮，共 8 进程、40 热轮。不与前述原版/
优化后序列混算。双方为 CPU F32、8 线程，官方 PyTorch 2.7.1+cpu，inter-op=1，
OMP/MKL/OPENBLAS=8；原生 Rayon=8。固定相同 ID/style/speed 与显式激励，官方权重
归一化按既有导出器验证的方式折叠，保留官方模型计算代码。计时均至主机完整 PCM，
排除前端、加载及写盘。输出样本数与整数时长一致；官方数值门禁仍另行报告。

| 固定输入声学 | 原生 RTF | 官方 RTF | 原生耗时 / 官方耗时 |
| --- | ---: | ---: | ---: |
| 短文，3.375 s 音频 | 0.25397 | 0.07393 | 3.44 |
| 长文，11.575 s 音频 | 0.27897 | 0.11558 | 2.41 |

进程均值 RTF 范围：短文原生 0.25282–0.25512、官方 0.06908–0.07878；长文原生
0.27083–0.28711、官方 0.11087–0.12028。这一结果表明当前 Windows CPU **没有
达到胜过同机官方的目标**。此前约 20% 的优化是相对 Windows 旧实现的阶段性收益。
本机现有 Torch 为 CPU 构建，本轮没有官方 CUDA 的同设备对照。

Mac 历史记录的长文组件 RTF 为 0.06522、公共 Engine 为 0.07259，分别使用 53.500 s
和 48.810 s 音频，含 g2pW；本轮 Windows 输入与前端模式不同。Windows CPU 当前
明显还有差距；Windows CUDA 的较低 RTF 也不能据此直接宣称胜过 Mac。
详见 [Mac 记录](kokoro-cpu-buffer-vector-2026-10-27.md)。

原始补充数据为 `official-comparison.json`、`official-comparison-v2.log` 和
`official-comparison-v2-*`。首次参考探针的随机张量回放适配失败，未完成的
`official-comparison-0-*` / `official-comparison-1-*` 不参与统计；修正后的 v2
完整序列才参与上述计算。原生生产代码未因这次补充对照发生变化。

## 准确性边界

**Windows 基线对官方的数值门禁未通过。** 未修改版本的完整声学 PCM SNR 为
25.2609 dB，整数时长相同，低于既有 40 dB 门槛；候选的完整 PCM 与 Windows
基线逐位相同，因而该问题没有被本轮性能优化修复。

原版及候选注入官方中间特征的独立解码 PCM SNR 均为 25.1928 dB，低于既有 60 dB 门槛。
这排除了“编码器 F0 差异是唯一原因”的解释，解码/激励的具体差异仍需独立隔离。
所有失败日志保留，既有门槛、夹具和预期结果未改动。

本轮输出保持和性能结论不代表 Windows 已完成官方数值、人工试听、实际播放、
干净机器安装或 macOS/Linux 回归验收。
