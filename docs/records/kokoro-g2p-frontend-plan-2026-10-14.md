# Kokoro 前端替换与多音字消歧训练规划

> 状态：规划中，未实现。本文接续 `tts-backend-plan.md` 未走完的"首选实验：词典覆盖 + 上下文多音字消歧"一线，记录 2026-10-14 的路线决策与验收设计。真实模型的数值、音频与性能验收届时另行单独记录；普通测试不下载、不加载模型。

## 背景与根因

- 退役 CPU 后端为 Kokoro（kokoro-v1.1-zh.onnx）与 ZipVoice。多音字错误的根因在 `tts-backend-plan.md` 已核查：Kokoro 是显式"拼音/注音 → 声学模型"两段路，当时 G2P 前端（`g2p/v11.rs`：jieba 分词、词组词典、变调规则）没有按整句语义消歧的神经模型，词典未命中即回落字级默认音。
- AR 后端（Nano/Qwen）不消除多音字歧义，只是把读音选择隐式学进模型：人名、生僻词、上下文不足的句子仍会错，且更隐蔽、无接口可纠。
- 官方无更新的中文权重可期（`tts-backend-plan.md:100`：作者公开中文模型仍是 Kokoro-82M-v1.1-zh，第三方量化只改开销不改读音）。

## 路线决策（2026-10-14）

**Kokoro 选择完整替换前端（重路线），而非读音覆盖轻路线**；决策理由是该任务作为小模型训练能力的首次端到端验证——数据蒸馏、微调、部署、自动验收全链路走通一次，训练管道与 CastGlean `docs/training-plan.md`（P0-P5）同构复用。

轻路线（规则 G2P 出音 → 消歧模型只翻案歧义字 → 经朗读副本读音覆盖注入，`Capabilities.pronunciation` 缝已有）**不废弃**：保留给 AR 后端使用，对接 Nano 的显式纠音语法（`tts-backend-plan.md:86` 标注待验证）。

## 方案分层

1. **消歧模型**：起步以 g2pW 建立基线（BERT 级、官方 ONNX checkpoint、简体与拼音输出，`tts-backend-plan.md:112`）；小说领域增量微调——人名读音、古风用词、口语语气词，数据用蒸馏管道产出，配方与 CastGlean 四分类器同构（encoder 全参微调）。变调/轻声/儿化等确定性规则保留在 G2P 内，神经模型只负责歧义字判定。
2. **前端归属纪律不变**（`tts-backend-plan.md:68`）：不把一个后端的注音/拼音结果传给其他后端。神经消歧模型输出标准拼音，可以共享；各后端自持拼音 → 音素/token 的映射，Kokoro 的 v1.1-zh 注音 token、声调与词表必须对齐，不混用旧 IPA 路径。
3. **注入接口**：`KokoroTts::synth` 当时内部自动调用 G2P、无外部音素注入的公开方法（`tts-backend-plan.md:117`）。替换前端需要为封装增加显式音素合成接口，拼音字符串不得当作普通正文送入。
4. **ZipVoice**：同为非 AR 声学前端，消歧模型与拼音→音素映射模式可复用，但其问题不止 G2P——前端是 vendored eSpeak（原生依赖，当年连同后端一起移除以简化工具链），且 CPU 实测 RTF 1.12–1.20 > 1、首 PCM 4.9–6.6s、峰值内存 ~1.1GB（`tts-model-tiers-acceptance.md`），听感本身是当时第二名。读音修复只是复活的必要条件，性能与前端重写需另立决策；一期只做 Kokoro。

## 验收设计

- 题型已有（`tts-backend-plan.md:269`）：银行/行走、重新/重量、长大/长夜、归还/还有；扩充小说人名与生僻词题。人工标注目标音，统计正确率与回归。
- 通过线：消歧准确率 ≥ g2pW 零样本基线 ≥ 规则基线；CPU RTF < 1 且持续生成快于播放（BERT 级单句推理为几十毫秒量级，非瓶颈）。
- **readback 自动判卷**：合成 → qwen3-asr 回读转写 → 对比目标读音，错误读音自动现形并积累为回归集，衔接读回闭环（`asr-readback-mainline-2026-10-09.md`）。
- 退役后端重新启用仍按 `migration.md` 约定手工配置，不做自动迁移。

## 战略位置

- 多音字解决 → Kokoro/ZipVoice 类 CPU 后端复活 → 无 GPU 的"本地草稿"档位成立。引擎三档：CPU 本地草稿、GPU 本地草稿+终稿、云端终稿（云端后端为另一条规划线，`Backend` trait 与 `Capabilities` 已具备引擎无关形状）。
- 本任务同时是训练能力验证的首个完整闭环：蒸馏数据 → 全参微调 → 部署（ONNX/ort 或 candle）→ readback 验收。

## 明确不做

- 不承诺 Kokoro 声学质量升级，只解决读音正确性与前端可替换性。
- 不改协议：`Capabilities.pronunciation` 与读音覆盖机制保持现状。
- 不恢复旧家目录回退与退役后端自动迁移。
