# Qwen3-TTS 1.7B Base CUDA 独立验收

## 模型、路径与基线

本轮验收对象是 **1.7B Base ICL**，不是 CustomVoice 或 VoiceDesign。此前的
0.6B CUDA 图数据不能替代它的验收；历史 1.7B RTF 也不能改名为本轮结果。
推理源码固定为 `11ceaba`，文档基线 `cd1089b`，没有为 1.7B 修改运行时算术。

模型严格按仓库清单准备在：

`~/.talechime/resources/qwen/models/1.7b-base/fd4b254389122332181a7c3db7f27e918eec64e3/`

全部 8 文件检查大小和 SHA-256。主权重 3,857,413,744 bytes，SHA-256 为
`38fc7fc51c5e776e840414b6fd443962e9411b9654888fd7913e4da643cb857c`；
codec 682,293,092 bytes，SHA-256 为
`836b7b357f5ea43e889936a3709af68dfe3751881acefe4ecf0dbd30ba571258`。
与本地 0.6B 清单哈希相同的 codec/tokenizer 文件用 NTFS 硬链接复用，不重复占用
权重空间。主权重从清单中的官方固定 revision 下载；下载临时文件也只在该目录中，
校验通过才发布为正式文件，没有把模型放到仓库或临时目录。

参考音频沿用既有验收参考，但 **用 1.7B 重新编码**，speaker embedding 为
2048 维、参考 codes 126 帧；没有复用 0.6B 的 1024 维 prompt。验收 prompt、
参考硬链接和身份元数据也在该模型的独立验收子目录，不覆盖既有音色、不注册为
产品音色、不修改用户配置。参考原文件保持不变；音频和 prompt 不提交 Git。

## C 盘清理

开始时 C 盘约 36.57 GiB 可用，D 盘约 15.18 GiB。盘点发现仓库 `target`
实际上是指向 `~/.codex/cache/talechime-target` 的 junction，D 盘工作区的
模型实验与编译产物仍占 C 盘。

| 已执行操作 | 逻辑文件大小 | 验证与保留边界 |
| --- | ---: | --- |
| 清理已完成下载的残片 | 5.566 GiB | VoxCPM 的完整 model/audiovae 与 MOSS Local 完整分片均先核对清单 SHA-256；只删除对应 `.part*` / `.incomplete` |
| MOSS 重复权重去重 | 10.955 GiB | 三份实验权重逐个与 `~/.talechime/resources` 正式副本核对 SHA-256；旧实验文件改成硬链接，旧路径仍可读 |
| 清理旧构建缓存 | 15.159 GiB | 只删除 `target/review/debug`、`target/tts-cli/release`，先检查实际绝对路径和无 Cargo/rustc 编译；保留当前 release/debug、源代码与实验结果 |

处理的逻辑大小合计 31.680 GiB，**实测空闲从约 36.57 增至 66.96 GiB**。
逻辑大小不等于文件系统实际释放空间，不能把二者混用。补齐 1.7B 后约 63 GiB

未批量清空 Codex 缓存、Temp 或用户下载目录，未删除有效独有权重、参考音频、
音色记录、配置、聊天记录及历史实验数据。操作审计与盘点保存在忽略目录
`target/tmp/qwen17-acceptance/{disk-inventory,cleanup-verified,cleanup-actions,model-receipt}.json`。

## CUDA 回归

使用既有显式测试入口，只把模型与 prompt 路径换成独立的 1.7B 资源，串行运行
`cuda --ignored --nocapture --test-threads=1`，**8 passed**：

- 真实 1.7B CP 帧图与直接 eager 算术对照，多组输入、早期输入重放、失败后停用。
- 真实模型 Concat KV 录制的清理/回退契约。
- 解码器多输入、形状切换、LRU 淘汰、表淘汰后回放与旧输出保留。
- 取消已经使用图的会话后，再次合成的可复用性及样本覆盖。
- 真实模型固定长度 Talker/decoder headroom 调查，仅为局部诊断。
- 三项无权重 CUDA 夹具：采样、整数取模、补齐注意力；不把合成 Q/K/V 当作
  真实模型动态 KV 的证明。

## 性能协议

Windows / RTX 5070 12 GiB，主模型 BF16、codec F32；本地权重与参考准备在计时外。
文本“山风吹过松林，星光照亮归途。”，seed 42、chunk_frames 10，沿用
`qwen_timing_probe` 默认生成选项，不调整采样、精度、帧上限或完成语义。

同一无 profiling release 二进制切换三种配置：

| 配置 | QWEN_CP_GRAPH | QWEN_DECODE_GRAPH |
| --- | --- | --- |
| eager | 0 | 0 |
| 仅 CP 图 | 1 | 0 |
| CP＋解码图 | 1 | 1 |

12 个串行独立进程按 E/C/B/B/C/E/E/C/B/B/C/E 执行，每种 4 个进程；任意两种
抽取后的顺序都是 ABBA ABBA。每进程加载模型一次，1 轮预热、5 轮热测，图录制
成本仍在调用计时内。先算每进程全部热轮均值，再报告组均值和进程均值范围。
范围不是置信区间。

请求 SM 锁频 2700 MHz，采样观测约 2692 MHz；保留平衡电源计划，结束解除锁频。
桌面 GPU 进程驻留，不能称完全独占。测量期间不编译或运行其他推理任务。
每轮完整/流式都在计时边界同步，codes、PCM、WAV 导出在计时外。

基准二进制 SHA-256：
`b1df019f44923b03bcc00f42620fd1f638bb5151e268a72489121de0c5d07c8b`，与此前 0.6B
解码图验收同一可执行文件，但不同模型的生成长度不能假定相同。

完整轮次、GPU/进程采样、分析脚本及摘要在
`target/tmp/qwen17-acceptance/`；所有权重和参考资源在 `~/.talechime`。

## 正式结果

三种配置、所有轮次均生成 52 帧、99840 samples，即 **4.16 秒音频**，自然 EOS。
完整和流式分别计时，流式为 5 个 10 帧块与一个 2 帧尾块，样本覆盖完整。

| 配置 | 完整合成 / RTF | 流式合成 / RTF | 首 PCM |
| --- | ---: | ---: | ---: |
| eager | 2.8463 s / 0.684 | 3.3973 s / 0.817 | 0.7665 s |
| 仅 CP 图 | 1.8732 s / 0.450 | 2.4013 s / 0.577 | 0.6052 s |
| CP＋解码图 | **1.8713 s / 0.450** | **2.0698 s / 0.498** | **0.6138 s** |

两项图相对同二进制 eager：完整耗时减少 **34.25%**、流式减少 **39.08%**、
首 PCM 减少 **19.92%**。在本输入上，稳态流式生成速度约为音频播放速度的
2 倍；首 PCM 不包括模型加载、参考准备或播放器预缓冲。

| 指标 | eager 进程均值范围 | 仅 CP 图 | CP＋解码图 |
| --- | ---: | ---: | ---: |
| 完整 / s | [2.8147, 2.8696] | [1.8406, 1.9105] | [1.8407, 1.9018] |
| 流式 / s | [3.3648, 3.4411] | [2.3816, 2.4192] | [2.0501, 2.0932] |
| 首 PCM / s | [0.7600, 0.7690] | [0.5973, 0.6137] | [0.6041, 0.6237] |

分阶段归因：CP 图使完整/流式分别减少 34.19% / 29.32%；解码图在 CP 已开启后，
使流式再减少 **13.81%**，达到 10% 门槛，范围不重叠。解码图对完整和首 PCM
没有明确变化（0.1% / −1.4%，范围重叠），不把波动写成收益或劣化。
最终总体百分比直接由本轮 eager/两图数据相除得到，没有跨实验相加。

12 进程 × 6 轮 × 5 类产物，共 **360 份**。codes、完整/流式 F32LE、完整/流式
WAV 每类跨三种配置的 SHA-256 各自唯一，包含预热轮；完整 PCM 和流式 PCM
分别对照，不要求两种解码方式彼此相同。优化没有改变本次生成的 token、PCM、
样本数或 EOS，不能仅凭这个样本把结论推广到所有文本与音色。

GPU 采样：整卡占用峰值 **9240 MiB（约 9.02 GiB）**，包含桌面程序和加载瞬态，
不是模型独占显存。温度 43–58°C，SM 采样范围 375–2692 MHz、中位数 2692，
内存频率 14001–14201 MHz、中位数 14001；空闲降频存在，不能写成全程固定频率。
结束已解除 SM 锁频。验收结束 C 盘约 **63.23 GiB** 可用，D 盘约 15.18 GiB。

## 结论与边界

**1.7B Base CUDA 的两项图优化已完成本轮独立验收**，不用 0.6B 的收益代替。
没有新增运行时改动、依赖或模型专用分支；复用已有按所有权划分的 CP session
和模型级无状态历史解码图。

本轮不包含：1.7B CustomVoice/VoiceDesign、官方 PyTorch CUDA 配对、Metal/CPU、
完整新语料矩阵、人工试听/ASR 回读和 30 分钟播放。这些不能因本轮图回放逐位一致
而写成已完成，也不能用不同生成长度的 0.6B 数据给出等 token 的模型速度排名。

本轮只新增文档与本地验收产物；代码未变，构建/静态检查沿用
[解码图审查](qwen-decoder-graph-2026-10-18.md) 的固定源码验证。本次补建 CUDA
release 参考探针、运行上述 8 项 CUDA 测试和 12 进程矩阵；仍观察到既有 Windows
`LNK4098` 链接警告，未改 CRT 或原生依赖。

验收后再次检查全部 8 个模型文件的哈希，均仍匹配固定清单；本轮文档本地链接、
`git diff --check`、workspace 格式检查和 `candle-performance` skill 校验通过。
