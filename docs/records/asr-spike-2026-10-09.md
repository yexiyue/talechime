# ASR 回读校验选型 spike（2026-10-09）

本文记录首阶段候选实验与当时待办；随后模型组已选定并接入，当前交付与原生证据见[主线记录](asr-readback-mainline-2026-10-09.md)。

本记录对应 [issue #2](https://github.com/yexiyue/talechime/issues/2)。这是开发期真实模型实验，不是产品接入、内容门禁验收或音质结论。模型、WAV、虚拟环境及原始 JSON/log 均在忽略目录 `target/asr-spike/`，不进入版本控制。

## 已确认的产品方向

- 首版同时提供独立回读报告接口，以及可选的校验/定向重合成；库 API 的模型准备与合成调用分开，资源可复用，调用过程中不隐式下载。
- 校验默认关闭，提供关闭、仅报告、校验并重试三种明确策略，避免多个互相制约的布尔参数。
- 流式合成也可开启门禁：每个实际合成片段先完整生成、校验和必要重试，通过后才交付 PCM；整章模式必须完成全部门禁后才播放。
- 主 ASR 发现疑点后，用不同模型复核；两者支持同一内容异常才自动重合成。重试保留原文、音色和风格，次数有界，耗尽后明确失败，不修改计划或撤回已交付音频。
- 未确认错误的疑点默认交付并附报告，严格拦截作为可选策略。同音/数字读法不能仅因双模型文字一致就升级为失败。
- 门禁模式 ASR 超时/执行失败停止该片段交付，返回可区分的校验错误；仅报告模式记录校验未完成并继续。不能冒充通过。
- 优先评估较新模型，包括 Qwen3-ASR；性能、识别效果和 Rust 接入成本分别验证。接口命名、阈值、限额与恢复/缓存契约尚未冻结。

## 环境与方法

Apple Silicon M4 Pro（Mac16,8），24 GiB 内存；Python 3.12.14；四个 CPU 线程。Qwen 官方原生 Transformers 模型使用 CPU FP32，另外试验 0.6B 的 MPS FP16；两个 ONNX 候选使用 CPU INT8。不能将这些 Python 数据写成 Candle/Rust 或 Windows/Linux 的性能结论。

核心环境：torch 2.14.1、transformers 5.19.0、sherpa-onnx 1.13.8、onnxruntime 1.31.0、kaldi-native-fbank 1.22.3、numpy 2.5.3、scipy 1.18.1、soundfile 0.14.0。完整版本保存在 `target/asr-spike/requirements.txt`。

随后按用户要求补测 Whisper large-v3-turbo，仍使用同一环境与语料。中文提示、贪心解码、最多 256 个新 token、不返回时间戳、不使用原文 prompt；以 `force_unique_generate_call=True` 保留原始生成序列和 EOS。此探针仅接受不超过 30 秒的片段，不启用 VAD、无语音门禁或温度回退，不能将其表现等同于官方 transcribe 全部默认策略。

语料共 16 个：Qwen TTS 的 8 个完整片段，VoxCPM 的 2 个完整片段，OmniVoice 的 1 个完整片段，以及一个对话片段派生的尾部截断（保留 65%）、中间删除（删除 30%–60%）、整段重复、纯静音、固定种子高斯噪声。原始片段来自已有开发期合成，不假定已由人逐字确认正确，因此不能统计为“干净语料误报率”。派生变体只验证粗粒度异常，不是自然漏读、单字吞字或真实合成重试样本。

所有音频统一为 16 kHz 单声道 PCM16。转写只提供中文语言提示，不提供原文提示词、热词或文本上下文。比对先做 NFKC、大小写归一及去标点/空白，保留数字形式、简繁与同音差异；SequenceMatcher 的差异坐标是归一化字符位置，不是产品要求的原文 UTF-8 字节范围，也不是 CER/WER 指标。

每个模型单独运行，记录加载耗时、每例耗时/RTF、转写、差异、异常及进程峰值 RSS。首例包含冷推理，之后重复一次作为预热；RTF 表使用 11 个原始片段的中位数，未包含加载耗时。单轮小样本只能作为选型信号，不代表长期运行、取消释放或并行 TTS/ASR 下的延迟保证。MPS 的进程 RSS 不是完整 GPU/统一内存峰值。

## 实测结果

全部五个候选完成，合计十组最终运行配置、160 条样例结果（不计预热和调试复跑）。各组均完成 16 例，没有执行错误；Qwen 与 Whisper 均未达到 256-token 输出上限。原始结果保存在 `target/asr-spike/{sensevoice,qwen06,qwen17,firered,whisper-turbo}*.json`，汇总为 `target/asr-spike/summary.json`。RTF 越低越快。

| 模型 / 推理路径 | 加载 s | 原始片段中位 RTF | 进程峰值 RSS GiB |
| --- | ---: | ---: | ---: |
| SenseVoice INT8 / sherpa CPU | 0.54 | 0.0116 | 0.91 |
| SenseVoice INT8 / 直接 ORT CPU | 0.40 | 0.0114 | 0.55 |
| FireRed CTC INT8 / sherpa CPU | 0.92 | 0.1089 | 1.95 |
| FireRed CTC INT8 / 直接 ORT CPU | 0.55 | 0.0386 | 1.27 |
| Qwen3-ASR 0.6B / Transformers CPU FP32 | 5.99 | 0.1081 | 4.31 |
| Qwen3-ASR 0.6B / Transformers MPS FP16 | 4.55 | 0.0868 | 3.41 |
| Qwen3-ASR 1.7B / Transformers CPU FP32 | 14.69 | 0.1904 | 8.72 |
| Qwen3-ASR 1.7B / Transformers MPS FP16 | 12.47 | 0.1136 | 8.08 |
| Whisper large-v3-turbo / Transformers CPU FP32 | 1.79 | 0.2455 | 4.90 |
| Whisper large-v3-turbo / Transformers MPS FP16 | 2.05 | 0.1013 | 0.61 |

注意：FireRed 的直接 ORT 路径未通过完整等价对照，所以较低 RTF 不能单独当作可用的加速成果。MPS 仅中位 RTF 较低，冷推理及加载仍有成本，RSS 也不能代替完整统一内存测量。

### 检出与误判线索

- 所有候选在尾部截断、中间删除、整段重复上都输出了明显的对应内容差异；静音/噪声也与原文明显不符。但只有一个源片段派生变体，不能由此宣称真实漏读检出率或误报率达标。
- SenseVoice 在静音和噪声上返回空文本；两个 Qwen 返回“嗯。”；FireRed 返回 `<sil>`。这些控制标记应与正文分离，空转写不能等同于转写执行失败。本工具保留原始输出，不实现门禁判定。
- 所有家族都将示例中的“她”转成“他”。双模型一致不证明 TTS 内容错误；同音排除必须先于自动重试。
- 日期金额例中，所有家族都输出“二零二六/十/七/一百二十八”。这是需要保留证据的形式差异，不能把文本替换计为漏读；数字归一化必须同时保留原文定位和歧义。
- “行长”被 Qwen 转成“营长”，被 SenseVoice/FireRed 转成“平长”。这不是可以仅靠两个模型投票认定错误的样本，仍需人工核查及明确多音字规则。
- 中英混读例中，SenseVoice 与 Qwen 保留 `hello world / enter`；FireRed CTC 参考识别器输出 `H HEARD / AN`。本轮没有体现 CTC 替代 Qwen 处理混读的优势。
- Qwen 0.6B 与 1.7B 的 CPU 归一化转写/差异结果在 16/16 例上一致；两种规格的 MPS 结果也没有新增内容识别收益。本样本不足以否定 1.7B 的其他场景优势，但不支持将其设为默认。
- 重复例的 diff 可以定位到开头或末尾，不同 ASR 标点/同音输出会改变编辑路径。复核应判断同一段音频的同类异常，不能要求归一化 diff 的起止坐标完全相同。
- Whisper 在截断、删除、重复变体中保留了对应差异；中英混读保留 `Hello World / Enter`，日期金额直接转成数字。但 CPU/MPS 贪心配置都在静音上输出“优优独播剧场——YoYo Television Series Exclusive”，噪声上输出“好”；不能用“非空转写”证明存在有效语音。
- Whisper 对“他/她”仍有混淆，且把原文“石阶”转成“时劲”。本轮没有体现其作为默认主筛查替代 Qwen 0.6B 的收益；这些原始音频未逐字试听，不能把差异全归因于 ASR 或 TTS。

### 原生接入探针

SenseVoice 直接 ORT 与 sherpa 参考实现的转写在 16/16 例上完全一致，说明本轮的前端、LFR、CMVN、CTC 解码组合可行；仍须补 Rust 前端、产品锁定 ORT 下的数值及取消/资源释放验证。

FireRed 直接 ORT 与参考实现仅 13/16 例文字完全一致。中英混读、石阶和钟声例存在差异；已校正 PCM 幅度、snip_edges 和高频边界，剩余差异尚未定位。不同 ORT/识别器版本与前端浮点数值都属于待验证因素，不将推测记为根因。此路径保留为实验，不作为首版已验收适配器。

Qwen 当前是官方 Transformers 对照，没有完成 Rust/ONNX 或 Candle 接入。sherpa 当前已有 Qwen3-ASR 模型与解码实现，可以进一步评估直接 ORT 的缓存、tokenizer 和自回归解码成本；不能把 PyTorch 实测直接当作该路径通过。

Whisper 初次统计误用了去除 EOS 的返回序列作为完成检查，已改成保留 EOS 的单次生成路径并重跑。曾尝试 `return_dict_in_generate=True`，在 MPS 上触发 Transformers 5.19.0 的 `EncoderDecoderCache.layers` 重组异常；该失败 JSON/log 保存在 `whisper-turbo-mps-return-dict-error.*`，未计入最终性能数据。采用公开的单次 tensor 返回路径后 CPU/MPS 各 16/16 正常完成，未修改第三方依赖。不能把调用路径异常记成模型内容错误。

### 本轮建议

优先推进 Qwen3-ASR-0.6B 为主筛查、SenseVoiceSmall 为跨模型复核；较新的 Qwen 模型优先，同时保留 SenseVoice 的速度与不同识别行为。CPU 成本优先的宿主可在同一校验器抽象下显式交换角色，不把模型名称写死进合成 API。1.7B 保留为可选候选，FireRed 在等价差异解决后再比较。该建议仍待扩大语料与原生接入验证，不是冻结的默认模型决定。

Whisper large-v3-turbo 保留为跨家族复核候选，具有现成 Candle 实现参考；本轮 CPU 中位 RTF 约为 Qwen 0.6B 的 2.3 倍，尚未显示额外检出收益。下一轮应补带无语音判定/低可信度处理的解码对照，观察能否降低与 Qwen/SenseVoice 相关的误判，再决定是否取代默认复核。候选必须可由宿主选择，不把三模型常驻或全部投票作为首版默认。

下一轮先验证 Qwen 的 Rust 接入路径、真实少字/漏句样本和双模型错误相关性，再确定同音/数字归一化及判定阈值。补齐取消、超时、片段容量、重试上限、已交付 PCM 不撤回及整章失败不播放的确定性测试后，才能称为产品门禁验收。

## 复现与工具边界

`tools/tts/asr_spike.py` 提供 `corpus` 和 `run`，执行时只加载调用方指定的本地模型目录。完整语料索引为 `target/asr-spike/combined-corpus.json`；各项记录保存 WAV SHA-256、原文、来源索引和变体类型。

```sh
uv venv --python 3.12 target/asr-spike/venv
uv pip install --python target/asr-spike/venv/bin/python \
  torch==2.14.1 transformers==5.19.0 sherpa-onnx==1.13.8 \
  onnxruntime==1.31.0 kaldi-native-fbank==1.22.3 \
  numpy==2.5.3 scipy==1.18.1 soundfile==0.14.0

target/asr-spike/venv/bin/python tools/tts/asr_spike.py corpus \
  --index /path/to/segments/index.json --output target/asr-spike/corpus

target/asr-spike/venv/bin/python tools/tts/asr_spike.py run \
  --backend qwen --model-path /path/to/pinned/qwen-model \
  --corpus target/asr-spike/combined-corpus.json \
  --output target/asr-spike/qwen06-cpu.json
```

同一 runner 支持 `qwen`、`whisper` Transformers 对照、`sensevoice`、`firered` 参考识别器和 `sensevoice-ort`、`firered-ort` 直接 ORT 探针。直接 ORT 探针复用 kaldi-native-fbank 做前端参考，没有完成 Rust 前端移植；LFR/CMVN/解码契约参考 sherpa 源码 revision `9db1af1871ed78cee9357c23898e5a7d8702d21a`。Python ORT 版本不同于产品锁定的 Rust ORT，不能据此认为原生依赖兼容性已验收。

当前工具不实现公共校验 API、重合成、播放门禁、缓存、超时取消或自动通过判定；错误被独立保存在报告，不转换成成功的空转写。普通 Cargo 测试不运行这些真实模型实验。
