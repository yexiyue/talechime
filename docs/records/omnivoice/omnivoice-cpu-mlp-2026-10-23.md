# OmniVoice CPU MLP 合并实验（2026-10-23）

基线 `25b0266` 已含 CPU attention 布局、分组 GQA、K/V 缓存及 greedy confidence gather。
本轮只验证 dense MLP 的 gate/up 合并，不改 QKV、down projection、精度、采样、
依赖或公共 API。另筛 SiLU×up 单操作原型，不接入该原型。

## 方案与内存判断的修正

Candle 当前 Linear 已将连续 rank3 输入展平后交给二维 GEMM，不存在漏掉此快路径的问题。
候选将 gate/up 的行主序权重拼成 `[6144,1024]`，一次 Linear 后沿最后一维拆分，
沿用原 SiLU、乘法、down projection；不额外物化 gate/up 的拆分视图。

初始探针同时持有原版与合并权重，按此双布局原型扩到 28 层会额外占 **672 MiB**。
这不是合并方案不可避免的常驻成本。核对固定 Candle 的加载器后改为：加载两路权重，
创建一个合并 buffer，gate/up 的回退 Linear 持有其前后两段行视图，随后释放原始
两路 Tensor。三路 Linear 共享同一存储，模型持有的 gate/up 权重元素数与原版相同。

生产 safetensors 后端每次 get 读取并生成 Tensor，不缓存已加载 Tensor；CPU from_slice
复制权重到独立存储，因此原始 gate/up Tensor 在 load 返回后可以释放。加载时仍有
每层约 24 MiB 的临时合并 buffer，不能声称没有加载成本或 RSS 必然相同。
调用者若以 TensorMap 等后端自行保留源 Tensor，其外部存储生命周期另计。
既有 K/V 缓存 224 MiB 不变，不把它算成本次增量，也不凭 RSS 推算权重字节数。
forward 的 up 视图仍持有整个 gate/up 输出 buffer，直到乘法消费结束；相比两路独立
输出可能延长 gate 半边的寿命。batch2/seq157/FFN3072 时这半边约 3.68 MiB，
所以不声称没有临时激活开销。

只对不可变、连续权重的 Accelerate CPU F32、hidden=1024/intermediate=3072、SiLU 模型建立合并权重。
forward 只在连续 rank3、seq>=8 时合并计算；短输入、非连续输入和其他 rank 使用共享
行视图执行原先两路 Linear。其他 dtype、设备、几何、激活和可变 VarMap 权重均不合并。
仍通过 Candle 原构造器加载，保留初始化提示、权重更新和 linear tracing span。

## 完整 MLP 探针

`cpu_mlp_probe` 加载真实第 0/27 层权重，输入为固定 xorshift 合成 F32，batch2。
测量包含 gate/up、SiLU、乘法、down 和相同形状的残差消费，不包含 norm/attention。
同时比较完整 gate、up 投影和最终 MLP 位模式。所有所测候选位差为零。

最终 `activation-*` 每进程顺序 0/1/2/3/4/4/3/2/1/0，每组 3 预热、20 热轮。
0=原版；1=合并后直接使用拆分视图；2=拆分后 contiguous；3=再预转置合并权重；
4=两路原投影加 SiLU×up 单操作。常用 seq157 三个独立进程，均无构建活动观测。
各列为完整 MLP 微秒，不将阶段值相加或乘层数/步数当作生产耗时。

| 进程 | 原版 | 合并视图 | 拆分连续化 | 预转置合并 | SiLU×up 原型 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 3207.530 | 3174.134 | 3303.435 | 3320.388 | 3241.249 |
| 2 | 3304.182 | 3160.005 | 3319.483 | 3319.974 | 3206.817 |
| 3 | 3232.258 | 3172.957 | 3338.035 | 3343.032 | 3228.200 |

mean-of-means 原版 **3247.990→3169.032 µs（-2.43%）**，合并视图三个进程方向一致。
这是单层热权重、合成激活的组件收益，探针没有生产路由检查，不代表整条 stage0。
探针为交错比较同时保留多份布局，其工作集与生产单份权重实现不同。

seq1/7/33/287 和第27层仅为额外单进程筛查：seq7 合并视图更慢，因此生产短形状回退。
seq33 某些组出现无构建活动观测的明显离群值，保留原始数据，不算成稳定的形状收益。
初始 `local-*` 探针把原版 gate/up 投影均放在 SiLU 之前；最终版本改为生产的
gate→SiLU→up→multiply 顺序并重新测量，不混用初筛与最终数据。

拆分后显式连续化、额外预转置均未显示完整 MLP 收益，不进生产。
SiLU×up 原型复用 Candle feature-selected SiLU，并在同一输出 Vec 上乘 up；它减少
一个中间张量，但常用形状三个进程的改善方向不一致，未显示可信完整 MLP 收益。
它还需要初始化输出 buffer，只保留在 example 私有模块中，不引入生产自定义操作。

## 普通检查与边界

CPU 35 项、Metal 48 项 lib 测试通过，Metal all-targets Clippy 与 lib/examples rustdoc
warnings denied 通过。MLP 新测试比较完整输出位模式：batch1/2、seq1/7/8/33/157、
连续/非连续、rank2/4 回退、重复调用、其他激活、非连续权重回退、Metal 原路径及 VarMap 权重更新。
普通测试不下载模型，未验证其他 Apple 芯片/系统版本或 AMD 实机。

有限样本逐位相同不保证所有 BLAS 平台/形状都相同，不扩大到未测几何与激活。
没有通过放宽数值门槛、改 seed、改步数或减少上下文获得收益。

## 保留依据

保留单份权重的合并视图路径：三个独立进程的完整 MLP 局部收益方向一致（约 2.43%），
数值/回退测试及短长真实输出通过；不新增常驻权重副本、依赖或运行时实验开关。
仍有加载临时拷贝与激活寿命代价，按其收益、实现复杂度和维护成本整体判断，
没有套用整链最低百分比门槛。合并权重双份常驻、显式拆分连续化、额外预转置及
SiLU×up 自定义操作均未进入生产。

本轮未确认稳定的整链增量，也没有证明 CPU 已追平官方。进一步优化应细分真实
forward 的算子/布局成本；官方组件参照表明启用同一 BLAS 配置仍不等于同一执行路径。
