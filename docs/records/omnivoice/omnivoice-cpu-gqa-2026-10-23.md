# OmniVoice CPU 分组 GQA（2026-10-23）

基线为 `c905eed`，已包含上一轮 Accelerate CPU K 转置视图优化。本轮只验证分组 GQA，
不叠加预转置权重，不改 dtype、采样、依赖、公共 API 或 Metal 实现。

## 实现和数值边界

原 CPU 路径先 repeat_kv，再以 `[B,H,S,D]` 做 QK、mask、softmax、PV。
2:1 GQA 中相邻两个查询头共享一个 KV 头，因此可以把 Q 视为 `[B,KV,2S,D]`，
直接和 K 的转置视图相乘；结果恢复 `[B,H,S,S]` 后沿用原 mask/softmax，
再把概率视为 `[B,KV,2S,S]`，与连续化后的 V 相乘，恢复 `[B,H,S,D]`。
不重复 K/V，两个 matmul 的 BLAS 调用次数各减半。V 的必要连续化仍在计时范围内。

仅匹配 Accelerate CPU F32、连续 Q/K、head_dim=128、2:1 GQA、seq>=8、
相同 batch/序列长度与 K/V 形状。小形状可能选择数值不同的 BLAS 路由，
所以 seq<8 保持原路径。其他设备、dtype、头比例和不支持布局均回退。
seq>=8 是本轮验证范围，不是跨平台 BLAS 快路径的通用阈值。

普通测试直接与 repeat_kv + 原 attention_manual 比较完整位模式：
batch 1/2，seq 1/7/8/33/157/179/287，dim 8/128，有/无 mask、非连续 V、
重复调用，以及非连续 Q/K、非 2:1 头比例的回退。25 项 CPU、36 项 Metal 测试通过；
Metal all-targets Clippy、lib/examples rustdoc warnings denied、格式检查通过。
普通测试不下载模型；未验证 AMD 实机性能。
