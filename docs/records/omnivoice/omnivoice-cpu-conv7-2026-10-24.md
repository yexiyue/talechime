# OmniVoice CPU 7-tap 布局优化（2026-10-24）

本轮基于 `0da2857`，保留 decoder 中 dilation=1 的受限 CPU F32 7-tap 卷积布局优化。
固定 130 帧完整 decoder **356.828→297.541 ms（-16.62%）**，短长完整输出逐字节一致。
整链两组观测增量为 0.46% / 1.23%，仍不确认稳定整链增量或追平官方。
配套 [逐进程原始轮次、输出哈希与二进制清单](omnivoice-cpu-conv7-2026-10-24.json)。
原始日志、receipt、冻结二进制和驱动在工作树 `target/perf/omni-cpu-conv7-real/`；
复用 `target/perf/omni-cpu-attribution/` 的真实张量和固定 codes，不提交张量或音频。

## 问题与实现

固定 Candle `2266099d92265112ecc0d56ecee1761e3cc2ac00` 的 CPU Conv1d 已使用
Accelerate GEMM，但通用 im2col 先生成 NLC 窗口，GEMM 后再逐元素复制回 NCL。
因此不能将 CPU 差距一概归因于漏开 feature，也不能仅从已使用 BLAS 推断没有优化空间。

候选仍然是 im2col 加 GEMM：用 padding/unfold 视图，按 `[batch,input_channel,tap,time]`
物化窗口，然后 `weight × columns` 直接输出 NCL。保留 `[input_channel,tap]` 收缩顺序，
不改变 bias、Snake、残差和采样；不新增内核、卷积算法、依赖、公共 API 或运行时实验开关。
NCL 窗口将时间轴保留为连续的长行，避免原 NLC 窗口沿输入通道频繁跨行读取，
并省去 GEMM 后从 NLC 到 NCL 的输出物化。
改变 BLAS 矩阵几何仍有浮点风险，有限逐位对照不能证明任意输入或其他 BLAS 版本上恒等。

生产入口仅从 decoder residual unit 调用；要求 Accelerate、CPU F32 输入和权重、dense、
连续布局、方阵通道 32/64/128/256/512、kernel=7、stride=1、padding=3、dilation=1、groups=1，
输入通道匹配、batch 非空、时间长度至少 8 且为 8 的倍数。
首个上采样 stride=8，当前真实 residual 输入位于这个长度格点。
不符合条件时继续原 Conv1d，dilation=3/9 和 decoder 首尾非匹配卷积不进入候选。
参考音频编码、Metal、CUDA、GGUF lazy 权重入口保持原实现。

候选仍物化完整 `7×` 窗口并额外 padding，不能称为零复制或低内存算法；
没有单独验证峰值内存下降。权重 reshape/broadcast 视图不持有新的长期权重副本。

## 实验协议

- M4 Pro / 8P+4E / 24 GB，macOS 26.6.2；release，CPU F32，Accelerate。
  Rayon/VecLib/OMP 请求 8 线程，不等同于直接观测内部 AMX 或实际线程数。
- 复用已验收 pointwise 优化后的生产二进制作为 A。`0da2857` 只比 `3e0623e` 新增离线
  MLP 探针和记录，运行时代码相同；基线二进制不是本轮重新编译的吞吐测量。
  B 按相同 `omnivoice,performance-tools` feature 构建，不启用 Metal。
- 初筛三进程对照原路径、显式 NLC 窗口、显式 NCL 窗口；随后实际受限 helper 再测三进程。
  五个 block 均使用真实 130 帧 decoder 的 res_unit1 输入、真实权重和真实残差。
- 每个 case/边界/variant 预热一次；每个候选三个 group 的 ABBA，每 slot 三次调用，
  轮换候选顺序。边界分别为 conv+bias，以及 conv→Snake2→已保留 1×1→残差。
  消费者不含前置 Snake1。完整消费者与子算子重叠，不能累加为生产耗时。
- 每个 case/variant 各两次对照完整 conv 与消费者 F32 位；原路径还与归档输出逐位对照。
  数值检查在计时外，正式局部计时不做导出或逐位比较。
- 固定 codes 完整 decoder：1/7/130 帧及全部 11 个长文本分段，各自进程 ABBA，
  每进程首次解码一次、热测五次。记录首次解码但不混入热均值；首次含惰性初始化。
  热测包括 codes 到 Tensor 的准备，模型入口准备和 WAV 导出在计时外。
- 短文本整链另测 ABBA，每进程 1 预热、3 热轮；正式吞吐关闭 codes dump 和阶段同步。
  短长完整输出另用 dump 进行对照，采样、输入、音色和种子派生不变。

## 局部结果

初筛 NCL 窗口的消费者改善约 59%–73%；最终 helper 的独立复核如下。
各格为一个进程的组内均值，列出三进程，单位 ms。

| block / 输入 | 原消费者（进程 1 / 2 / 3） | 候选消费者（进程 1 / 2 / 3） | 本组耗时减少 |
| --- | --- | --- | --- |
| 0 / `[1,512,1040]` | 4.880 / 4.946 / 4.920 | 2.141 / 2.184 / 2.184 | 55.61%–56.14% |
| 1 / `[1,256,5200]` | 10.380 / 10.092 / 10.571 | 3.535 / 3.586 / 3.678 | 64.46%–65.95% |
| 2 / `[1,128,20800]` | 17.952 / 17.943 / 18.045 | 5.893 / 5.845 / 5.976 | 66.89%–67.42% |
| 3 / `[1,64,41600]` | 17.116 / 17.493 / 17.432 | 5.404 / 5.519 / 5.520 | 68.34%–68.45% |
| 4 / `[1,32,124800]` | 26.313 / 25.943 / 26.220 | 7.912 / 7.808 / 7.976 | 69.58%–69.93% |

不能把初筛和最终组的绝对时间相减归因于 helper 开销；对照各自的组内原路径。
显式 NLC 对照也有小幅收益，但明显弱于 NCL，只保留离线对照，不设运行时选项。

以下为三个最终进程的隔离组件均值，单位 ms，仅用于解释布局成本：

| block | NLC / NCL 窗口物化 | NLC / NCL GEMM | NLC / NCL 输出布局与 bias |
| --- | --- | --- | --- |
| 0 | 1.821 / .202 | 1.307 / 1.249 | .952 / .036 |
| 1 | 4.689 / .435 | 1.489 / 1.524 | 2.429 / .090 |
| 2 | 9.941 / .885 | 1.860 / 2.151 | 5.000 / .179 |
| 3 | 9.233 / 1.110 | 1.250 / 1.323 | 4.818 / .176 |
| 4 | 14.391 / 1.661 | 1.886 / 1.790 | 6.747 / .253 |

GEMM 的变化小于窗口物化和输出复制的差距，甚至有个别几何更慢。
这是“布局可优化、并非只缺 BLAS feature”的证据；没有测硬件计数器，不能直接称作带宽极限。
显式 NLC 窗口不是 Candle 私有 im2col 的直接隔离计时，两者实现不同；
原 Conv1d 与最终 helper 的整体消费者对照才是保留依据，不能将表中组件相加预测整链。
