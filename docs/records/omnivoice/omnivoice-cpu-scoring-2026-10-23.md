## CPU confidence gather：生产候选

原 CPU 贪心评分先 argmax 取 token，再 max 扫一遍完整词表取 confidence。
固定 Candle 的 CPU ReduceIndex 中，argmax/max 使用相同的比较与首元素初始化，
分别返回所选索引/值。贪心时直接 gather 该索引的值，可以避免第二次扫描；
不改变 log_softmax、guidance、mask 或 token 的选择。

复用既有 Metal 贪心分支，只扩到 CPU F32 且 log_probs 连续的情况。
CPU gather 要求源/索引连续；不支持的布局/dtype 保持 max，其他设备不扩大路由。
CPU 随机采样提前返回，仍取完整分布的最大 confidence，不取采样 token 的分数。
生产增量为一个私有条件分支，没有新增缓存、运行时开关或请求状态。

## 局部最终复测

select 形状 `[1,8,130,width]`；完整 scoring 包含两路 log_softmax、CFG=2、再次

## 保留与边界

保留 CPU F32 连续贪心路径的 confidence gather：三个独立进程的局部选择和完整 scoring
收益可重复，完整输出及普通回归通过；没有新增权重缓存，生产增量仅一个条件分支。
依据是局部收益、输出保持和低维护成本，不是整链最低百分比门槛。
输出头裁剪仍只留离线探针，没有通过真实模型整链验收；未把它混入候选二进制。

本轮没有追平官方的实测结论。当前主要开销仍需从真实 stage0 forward 的
GEMM/MLP 等路径继续定位，不再把较小的 scoring 收益当作整体差距已解决。
