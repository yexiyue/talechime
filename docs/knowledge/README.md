保存和迭代开发中的规划、技术决策与可复用经验。开始任务先查相关条目，再核对当前源码、锁定依赖和所属规格；日期、平台或版本不同的历史结论不是当前行为的证明。维护流程见 [AGENTS.md](../../AGENTS.md#开发与知识积累工作流)。

## 新内容放在哪里

| 位置 | 职责 |
| --- | --- |
| `knowledge/plans/` | 持续迭代的阶段规划、依赖和待验证问题，明确候选/已决定/已实现/已验证；不代替已批准的实施任务 |
| `knowledge/decisions/` | 有背景、备选方案、取舍依据、影响和重新评估条件的技术决策 |
| `knowledge/lessons/` | 故障触发条件、根因、处理方式、验证与预防；有实际条目时再创建目录与文件 |
| [OpenSpec](../../openspec/changes/) | 功能要求、设计和执行任务；知识笔记不自动扩展范围或授权实现 |
| [历史台账](../records/README.md) | 特定日期、版本、设备的验收、实验及阶段规划快照，保留原始结论与失败边界 |
| [开发规范](../development.md)、[架构](../architecture.md)及后端指南 | 当前可执行的工程要求、公开行为与使用方式 |
| [AGENTS.md](../../AGENTS.md) | 简短且长期必须遵守的约束，以及开发工作流 |

同一事实只维护一个来源，通过链接连接知识、规格和证据。可复用经验经验证后提炼进领域指南或开发规范；只有长期稳定的约束提升到 AGENTS，案例和原始依据保留在原处。

## 一条记录需要什么

记录日期与状态、适用版本/平台、问题或目标、触发条件、原因与备选取舍、处理方式、验证证据、相关链接和未解决项。简单结论不必机械地拆出全部章节，也不为每次会话生成流水账。

原生依赖写清源码 revision 和 feature 组合；真模型证据写清权重/转换来源、输入、精度、实际设备与执行路径。数值对照、有效 PCM、人工听感、性能测量、宿主集成和发行分别说明，普通测试不能下载模型或冒充真模型验收。具体门禁复用已有指南，不在此维护第二套限额或命令。

新证据推翻旧结论时，更新现行知识与领域指南，并链接新证据；历史台账不覆盖旧数据，可添加注明日期的更正或新记录。不得抹去未通过项、撤回实验或未执行的人工试听。密钥、私人音频/正文、模型权重和运行产物不进入知识库。
