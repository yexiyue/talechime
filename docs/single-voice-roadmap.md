# 单音色朗读主线

2026-10-31 用户选定两款固定参考，暂时结束音色扩展。主线按 [Talechime #6](https://github.com/yexiyue/talechime/issues/6) 推进，先完善 Talechime 独立的单音色基线，再消费上游演绎规划。

## 已确定的参考

- 御姐第一款：冷艳低音，库 ID `vcchar1031-yujie-cold`。
- 萝莉／甜萌第一款：软糯轻甜，库 ID `vcchar1031-cute-soft`。

它们是用户选择的 Qwen VoiceDesign 原创音色。两个 ID 只用于本地验收，库资产及指纹保存在运行清单中，不作为所有安装都具备的内建音色。不更换用户当前默认音色，不删除其他候选。

## 当前推进顺序

1. **首次使用正确性**：库音色首次物化后，已加载后端必须能看见它。已为 VoxCPM 接通元数据刷新，直接合成与计划两条库入口均触发；不重载权重，不改变活动计划绑定。其他后端首用矩阵继续逐个验收。
2. **无规划多段基线**：用两款固定参考、同一份原创六段文本、VoxCPM2 Q8 / Metal / seed 7 验证连续朗读。记录源摘要、参考指纹、首次使用状态和音频。生成成功与人工听感、播放完成分开，不把多段基线当作整章结论。
3. **组段和风格边界**：审计同 voice/style 的可合并范围及不同 style 的硬边界，避免标注过碎导致每句话重起；不跨角色/风格边界无条件合并，也不突破模型预算。
4. **先人工规划对照**：同正文同音色比较无规划与少量人工风格建议，确认现有后端指令确实改善表达，再接 CastGlean 的线上 GLM/MiniMax 规划。后端能力、缺失标注和显式降级分别处理。
5. **整章与生命周期验收**：扩到完整章节和换 seed 复现，继续验证漏读/重复、固定参考、缓存身份、取消、迟到结果和实际播放恢复。自动指标只标记疑点，听感由用户确认。

本轮不继续扩音色、不推进多角色选角或新模型；MOSS VoiceDesign Metal 的 `invalid MOSS logits` 问题保留未完成，后置处理。Talechime 不直接调用线上 LLM，CastGlean 提供后端无关的语义规划，宿主负责映射到朗读计划。

## 首次使用刷新契约

`Backend::refresh_reference_voices` 是一个有默认实现的附加钩子。库入口成功物化了加载时未列出的音色后，调用该钩子，再进行正常合成/计划校验。静态目录无需操作；维护参考目录快照的后端应实现元数据刷新。

VoxCPM 只在完整读取新清单成功后更新音色 ID 与显示名；损坏清单返回错误并保留旧快照。不改变 backend/model、默认音色、参数、设备或模型 owner。参考文件有效性与模型编码仍由原有物化、缓存与推理路径验证。
